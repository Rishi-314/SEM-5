1 Storage Options & Features
A. Storage models in the cloud
ModelWhat it isWho uses it
Public Cloud Storage Storage provided by third-party services (Google Cloud, AWS, Azure); data stored on shared infrastructure. Startups, businesses needing scalability, collaborative projects.
Private Cloud Storage Dedicated storage environment used by a single organization, on-premises or hosted by a provider. Companies handling sensitive data — banks, healthcare providers.
Hybrid Cloud Storage Combination of public and private cloud storage; businesses choose where to store data based on security and cost. Companies needing both secure storage and flexible scalability.
Multi-Cloud Storage Data spread across multiple cloud providers to avoid dependence on a single vendor and improve reliability. Enterprises enhancing performance and disaster recovery.
Community Cloud Storage Shared cloud infrastructure used by multiple organizations with similar needs — government agencies, research institutions. Groups needing a shared but secure cloud environment.
B. Features of a cloud storage system
  • Greater availability of resources.
  • Easy maintenance — one of the key benefits of cloud computing.
  • Large network access.
  • Automatic system operations.
  • Security — a major component; can secure all networks.

2 Block · File · Object Storage
A. Block-based storage system
  • Example: an 80 MB file might be divided into many blocks.
  • The operating system manages these blocks and combines them to represent the file.
  • Think of block storage as a large notebook divided into numbered pages — the system can directly access page 25 without reading pages 1–24.

Characteristics

  • Very fast read / write operations
  • Low latency
  • Suitable for databases and virtual machines
  • Blocks can be modified independently
  • Usually accessed as a disk / volume by an operating system
B. File-based storage system
  • Users access files through a familiar directory / folder structure.

Characteristics

  • Uses files and directories
  • Easy for users to understand
  • Supports file sharing
  • Suitable for shared applications
  • Uses file paths to locate data
C. Object-based storage system
  • Data is stored as an object. Each object contains:
    • Data — the actual content
    • Metadata — information about the data
    • Unique identifier / key — used to locate the object

Characteristics

  • Highly scalable
  • Suitable for very large amounts of data
  • Stores metadata with the data
  • Accessed using unique keys / URLs or APIs
  • Excellent for unstructured data
Memory hook: Block → Disk · File → Folder · Object → Bucket.
D. Easy way to remember + comparison
  • Block → Disk — used when you need a high-performance virtual disk.
  • File → Folder — used when you need a shared file system.
  • Object → Bucket — used when you need to store huge amounts of files, images, videos, backups and other unstructured data.
  • Block = optimized for performance · File = shared file access · Object = massive scalability and unstructured data.

3 Structured vs Unstructured + Cloud Storage
A. Structured storage in the cloud
  • Stores data in a predefined format, such as rows and columns, making it easy to organize, search and analyse.
  • Typically managed using a Relational Database Management System (RDBMS).

Characteristics

  • Data organized in tables
  • Fixed schema
  • Supports SQL (Structured Query Language)
  • High data integrity and consistency
  • Suitable for transactional applications

Advantages

  • Fast querying using SQL
  • High accuracy and consistency
  • Supports transactions (ACID properties)
  • Easy reporting and analytics

Limitations

  • Difficult to handle changing data structures
  • Requires a predefined schema
  • Less suitable for multimedia and large unstructured datasets
B. Unstructured storage in the cloud
  • Stores data that does not follow a predefined format or schema.
  • Designed to manage large volumes of diverse data: documents, images, videos, emails, audio files, social media content.

Characteristics

  • No fixed schema
  • Highly scalable
  • Stores large files efficiently
  • Metadata is used for identification
  • Suitable for object storage systems

Advantages

  • Stores any type of file
  • Highly scalable
  • Cost-effective for large datasets
  • Easy backup and disaster recovery
  • Suitable for big data applications

Limitations

  • Complex searching and indexing
  • Limited support for complex transactions
  • Data analysis often requires additional processing tools
Memory hook: Structured = tables + SQL + ACID · Unstructured = schema-less + scalable + metadata.
C. Unstructured storage using Google Cloud Storage
  • Google Cloud Storage (GCS) is a scalable, secure and durable object storage service provided by GCP.
  • Designed to store and retrieve large amounts of unstructured data from anywhere in the world.
  • Stores data as objects within buckets.
  • Bucket: a logical container used to store objects.
  • Object: the actual file along with its metadata.

Real-world example — photo-sharing app

  • Users upload images.
  • Images are stored as objects in a Cloud Storage bucket.
  • Metadata (user ID, upload date, image URL) is stored in a database.
  • Applications retrieve images directly from Cloud Storage.
  • Older images are automatically moved to Coldline or Archive using lifecycle policies.
4 SQL Managed Services · Cloud SQL
A. What is a SQL managed service?
  • Cloud-based relational database service where the provider manages database administration tasks: installation, configuration, backups, updates, security, replication and scaling.
  • Users focus on developing applications instead of maintaining database servers.

Features of SQL managed services

  • Fully managed relational database service
  • Automatic backups and recovery
  • High availability and failover support
  • Automatic software updates and patching
  • Data encryption at rest and in transit
  • Automatic storage scaling
  • Performance monitoring and optimization
  • Built-in disaster recovery options
  • Easy integration with cloud services
B. Exploring Google Cloud SQL
  • Fully managed relational database service provided by Google Cloud Platform (GCP).
  • Simplifies setup, maintenance, management and administration of SQL databases in the cloud.

Supported engines

MySQLRDBMSOracleWeb applications, websites
PostgreSQLRDBMSPostgreSQL Global Development GroupEnterprise apps, analytics, complex databases

C. Cloud SQL features
  • Fully Managed Service — Google manages installation, updates, patching and maintenance.
  • Automatic Backups — scheduled backups with point-in-time recovery.
  • High Availability — automatic failover using regional replicas.
  • Read Replicas — improve read performance by distributing read traffic.
  • Automatic Storage Increase — storage expands automatically as needed.
  • Security — IAM integration, SSL/TLS encrypted connections, data encryption at rest, firewall rules, private IP support.
  • Monitoring — integrated with Cloud Monitoring and Cloud Logging.
  • Scalability — vertical scaling (CPU, RAM) and storage scaling.
Memory hook: Cloud SQL = managed MySQL / PostgreSQL / SQL Server + backups + HA + read replicas.
5 Cloud Spanner
A. What is Cloud Spanner?
  • Fully managed, globally distributed relational database service offered by GCP.
  • Combines the benefits of traditional relational databases (SQL, ACID transactions, schemas) with the scalability and high availability of NoSQL databases.
  • Designed for mission-critical applications that require horizontal scalability, strong consistency and global availability.
  • Automatically distributes data across multiple servers and regions while maintaining consistency.
  • Google manages infrastructure, replication, backups, updates and scaling.
B. Key features 1–5
  1. Fully Managed Service — Google manages installation, configuration, updates and maintenance; no server administration required.
  2. Horizontal Scalability — scale from a few gigabytes to petabytes; add or remove compute nodes without downtime.
  3. Global Distribution — data distributed across multiple regions; supports worldwide applications with low latency.
  4. Strong Consistency — all users see the latest committed data; uses Google's TrueTime technology for synchronized transactions.
  5. ACID Transactions — Atomicity, Consistency, Isolation, Durability; suitable for financial and enterprise applications.
C. Key features 6–10
  1. High Availability — automatic replication across zones or regions; automatic failover on failures.
  2. SQL Support — ANSI SQL with tables, joins, indexes, transactions and foreign keys.
  3. Automatic Backups — scheduled backups, point-in-time recovery, easy restoration.
  4. Security — IAM-based access control, encryption at rest and in transit, audit logging, private networking support.
  5. Monitoring — integrated with Cloud Monitoring, Cloud Logging and Cloud Audit Logs.
Memory hook: Spanner = Relational + Global + Strong consistency + TrueTime + ACID.
6 NoSQL Managed Services
A. What is a NoSQL managed service?
  • Cloud-based database services designed to store and manage non-relational (NoSQL) data.
  • Support flexible schemas and are optimized for large volumes of structured, semi-structured and unstructured data.
  • Provider handles provisioning, maintenance, backups, scaling, security and software updates.
  • NoSQL (Not Only SQL) stores data in formats other than tables; provides high scalability, low latency and flexible data models — ideal for web, mobile, IoT and big data applications.
B. Cloud Firestore
  • Fully managed, serverless document database.

Features

  • Stores data as collections and documents
  • Real-time data synchronization
  • Automatic scaling
  • Offline support for mobile apps
  • ACID transactions
  • Strong consistency
  • Secure access using IAM and Firebase Authentication

Applications: mobile applications, web applications, chat applications, real-time collaboration tools.

C. Cloud Bigtable
  • Google's fully managed wide-column NoSQL database.
  • Based on Google's internal Bigtable technology, which powers Google Search, Gmail and Google Maps.
  • Stores data in rows and column families instead of traditional relational tables.
  • Optimized for large-scale storage, fast read / write performance and horizontal scalability.
  • Unlike SQL databases, does not support joins or complex relational queries.

Features

  • Fully managed — no server admin, automatic maintenance and software updates.
  • Horizontal scalability — scales to petabytes, supports billions of rows.
  • High performance — millisecond read / write latency; millions of operations per second.
  • High availability — automatic replication across clusters; multi-cluster deployments.
  • Flexible schema — columns can vary between rows; easy to accommodate changing data requirements.
  • Security — IAM-based access control, encryption at rest and in transit, private networking.
  • Integration — BigQuery, Dataflow, Dataproc, Vertex AI, Apache HBase API.
  • Backup and Recovery — automated backups, snapshot support, disaster recovery.

Applications: IoT data, time-series data, financial analytics, recommendation engines, large-scale analytics.

D. Cloud Memorystore
  • Managed in-memory database service supporting Redis and Memcached.

Features

  • Extremely low latency
  • Automatic management
  • High availability
  • Data caching
  • Session storage

Applications: website caching, gaming leaderboards, session management, frequently accessed data.

E. Cloud Datastore — NoSQL document store
  • Fully managed NoSQL document database service by GCP.
  • Designed to store large amounts of semi-structured and unstructured data with high scalability, reliability and automatic replication.
  • Note: has evolved into Firestore in Datastore mode — same Datastore API with enhanced capabilities.
  • Stores data as entities rather than rows and columns.
  • Each entity consists of properties, similar to fields in a document.
  • Supports flexible schemas — different entities can have different sets of properties.
  • Does not require predefined tables or fixed schemas — ideal for rapidly changing applications.
Memory hook: Firestore = document · Bigtable = wide-column · Memorystore = in-memory · Datastore = entity/NoSQL document store.

  • Open-source cloud computing platform used to build and manage Infrastructure as a Service (IaaS) clouds.
  • Allows organizations to create private and public clouds by managing compute, networking, storage and identity services through a web dashboard or APIs.

B. Nova & Neutron

1. Nova (Compute Service)

  • Responsible for creating, scheduling and managing virtual machines (VMs).

Features

  • Creates and manages virtual machines
  • Supports multiple hypervisors (KVM, VMware, Hyper-V)
  • Auto scheduling
  • Live migration
  • Scaling support

Applications: web servers, virtual desktops, enterprise applications.

2. Neutron (Networking Service)

  • Provides Networking as a Service (NaaS).

Features

  • Virtual networks
  • IP address management
  • Routers and firewalls
  • Load balancing
  • Floating IP support

Functions

  • Connects VMs
  • Creates isolated tenant networks
  • Provides external Internet connectivity
C. Keystone & Cinder

3. Keystone (Identity Service)

  • Manages authentication and authorization.

Features

  • User authentication
  • Role-based access control (RBAC)
  • Token management
  • Multi-tenant support
  • Identity federation

4. Cinder (Block Storage)

  • Provides persistent block storage volumes for virtual machines.

Features

  • SSD / HDD storage
  • Volume snapshots
  • Backup support
  • Dynamic resizing
  • High availability

Uses: database storage, VM boot disks, enterprise applications.

D. Swift & Glance

5. Swift (Object Storage)

  • OpenStack's distributed object storage service.

Features

  • Stores files as objects
  • Massive scalability
  • Data replication
  • Fault tolerance
  • REST API access

Applications: image storage, backup, multimedia storage, archives.

6. Glance (Image Service)

  • Manages virtual machine images.

Features

  • Stores VM templates
  • Version management
  • Image sharing
  • Snapshot support
  • Multiple image formats

Applications: fast VM deployment, standardized operating system images.

Memory hook: Nova = compute · Neutron = network · Keystone = identity · Cinder = block · Swift = object · Glance = images.
8 VMware · CloudStack · Data Lakes · Snowflake
A. VMware Suite
  • Collection of virtualization and cloud management products used to build private, hybrid and multi-cloud environments.

Features

  • Server virtualization
  • Live migration (vMotion)
  • High availability
  • Distributed resource scheduling
  • Storage virtualization
  • Network virtualization
  • Disaster recovery

Applications: enterprise data centers, hybrid cloud, virtual desktop infrastructure (VDI), business continuity.

B. Apache CloudStack
  • Open-source cloud orchestration platform used to deploy and manage IaaS clouds.

Features

  • Self-service portal
  • VM provisioning
  • Storage management
  • Network management
  • Multi-tenancy
  • API support
  • High availability

Advantages

  • Easy deployment
  • Supports multiple hypervisors
  • Automated infrastructure management
  • Open-source and cost-effective

Applications: private cloud, hosting providers, research institutions, enterprise virtualization.

C. Data Lakes
  • Centralized repository that stores structured, semi-structured and unstructured data in its original (raw) format.
  • Supports analytics, machine learning and big data processing.

Features

  • Stores all types of data
  • Massive scalability
  • Low-cost storage
  • Schema-on-read
  • Supports AI and machine learning
  • Integrates with analytics tools

Advantages

  • Cost-effective
  • Highly scalable
  • Supports big data analytics
  • Stores raw data
  • Flexible

Applications: business intelligence, machine learning, IoT analytics, healthcare analytics, financial analytics.

D. Snowflake
  • Cloud-native data warehouse platform that enables organizations to store, process and analyze large volumes of data.
  • Runs on cloud providers such as AWS, Microsoft Azure and Google Cloud.

Key features

  • Cloud-native architecture
  • Separation of storage and compute
  • Automatic scaling
  • High concurrency
  • Data sharing
  • Time Travel (historical data recovery)
  • Zero-copy cloning
  • Secure data sharing

Advantages

  • High performance
  • Elastic scalability
  • Minimal administration
  • Supports structured and semi-structured data
  • Multi-cloud deployment
  • Pay-as-you-use pricing

Applications: data warehousing, business intelligence, data engineering, data science, financial reporting, marketing analytics.

Memory hook: VMware = virtualization suite · CloudStack = open-source IaaS · Data Lake = raw data · Snowflake = storage + compute separated.
