1 SOA & Web Services
A. Service-Oriented Architecture — definition
  • Software design approach in which applications are built by combining independent, reusable and interoperable services.
  • Each service performs a specific business function and communicates with other services through standardized protocols such as HTTP, SOAP or REST APIs.
  • In cloud computing, SOA enables different cloud services to work together efficiently — making applications scalable, flexible and easy to maintain.
B. Real-world example — online shopping
  • Login Service — user authentication
  • Product Service — product catalog
  • Payment Service — online payments
  • Order Service — order processing
  • Shipping Service — delivery management
  • Notification Service — email / SMS alerts
Memory hook: SOA = Independent services + ESB + Registry + Contract.
C. Components of SOA
  1. Service Provider — creates and hosts services; makes them available over the network.
  2. Service Consumer — uses the services provided by the provider; can be a web app, mobile app or another service.
  3. Service Registry — stores information about available services; helps consumers discover required services.
  4. Enterprise Service Bus (ESB) — connects different services; performs routing, message transformation, security and communication.
  5. Service Contract — defines service interface, inputs, outputs and communication rules.
D. Web Services — definition & stack
  • Software component that enables communication and data exchange between different applications over the Internet using standard web protocols.
  • Allows applications developed in different languages and running on different platforms to interact seamlessly.
HTTP / SOAP / REST  →  XML / JSON Response
E. Web Services — components & features

Components

  • Service Provider — hosts and provides the web service.
  • Service Consumer (Client) — requests and uses the service.
  • Service Registry — stores service information for discovery.
  • WSDL — describes the service interface.
  • SOAP / REST APIs — communication protocols.

Features

  • Platform independent
  • Language independent
  • Reusable
  • Interoperable
  • Loosely coupled
F. Advantages & examples

Advantages

  • Easy integration
  • Supports distributed applications
  • Reusable services
  • Faster application development
  • Cost-effective

Examples

  • Payment Gateway APIs
  • Google Maps API
  • Weather API
  • SMS Gateway
  • Banking APIs
Memory hook: Provider → Registry → Consumer | WSDL + SOAP/REST | XML/JSON.
2 Web 2.0 & Web OS
A. Web 2.0 — definition & characteristics
  • Second generation of the World Wide Web focusing on user interaction, collaboration and content sharing.
  • Unlike Web 1.0 (static pages), Web 2.0 enables users to create, edit and share content.

Characteristics

  • User-generated content
  • Collaboration
  • Rich user interface
  • Social networking
  • Dynamic web pages
  • Interactive websites
B. Web 2.0 — examples, pros & cons

Examples: Facebook, YouTube, Wikipedia, Instagram, X (formerly Twitter), Blogger.

Advantages

  • Easy collaboration
  • Real-time communication
  • Content sharing
  • Better user experience
  • Community building

Disadvantages

  • Privacy issues
  • Security risks
  • Fake information
  • Data misuse
C. Web OS — definition & features
  • An operating system that runs primarily through a web browser.
  • Provides access to applications, storage and files over the Internet instead of relying on local installation.

Features

  • Browser-based
  • Cloud storage
  • Online applications
  • Multi-user support
  • Platform independent
  • Accessible from anywhere
D. Web OS — pros, cons & examples

Advantages

  • No installation required
  • Automatic updates
  • Access from any device
  • Lower hardware requirements
  • Easy backup and recovery

Disadvantages

  • Internet dependency
  • Security concerns
  • Limited offline functionality
  • Performance depends on network speed

Examples: Google Chrome OS, EyeOS, Ghost OS, Glide OS (legacy), Microsoft Windows 365 (Cloud PC concept).

Memory hook: Web 2.0 = user-generated + social · Web OS = browser-based OS + cloud storage.
3 Cloud Platform & Management
A. Components of a cloud platform
  1. Compute Services — Virtual Machines (VMs), containers, CPUs and memory allocation.
  2. Storage Services — object storage, block storage, file storage, database services.
  3. Networking Services — virtual networks, load balancers, firewalls, VPNs.
  4. Security Services — authentication, Identity and Access Management (IAM), data encryption, firewall protection.
  5. Monitoring Services — performance monitoring, resource utilization, error detection, alerts and notifications.
  6. Billing and Cost Management — usage monitoring, pay-as-you-go billing, cost optimization, budget management.
B. Cloud management functions
  1. Provisioning — allocating cloud resources automatically.
  2. Monitoring — tracking system performance, uptime and resource usage.
  3. Scaling — increasing or decreasing resources based on demand.
  4. Automation — automatic deployment, backup, updates and recovery.
  5. Security Management — user authentication, access control, encryption, compliance.
  6. Backup and Disaster Recovery — data backup, replication, recovery after failures.
C. Features of a cloud platform
  • On-demand resource provisioning
  • Self-service management
  • Auto-scaling
  • High availability
  • Resource monitoring
  • Cost optimization
  • Security and compliance
  • Multi-cloud support
Memory hook: Compute + Storage + Network + Security + Monitoring + Billing = cloud platform.

4 Exploring PaaS with App Engine
A. What is Google App Engine?
  • Platform as a Service (PaaS) provided by Google Cloud.
  • Enables developers to build, deploy and manage applications without worrying about underlying infrastructure.

Platform automatically handles

  • Server provisioning
  • Load balancing
  • Auto scaling
  • Security patches
  • Monitoring

Developers only focus on writing application code.

B. Architecture — 8 layers
1. Client / User
2. Load Balancer
3. App Engine Front End
4. Memcache
5. Cloud Storage (static)
6. Datastore / Cloud SQL
7. Task Queues
8. Backend / Batch Application
  1. Client / User — access via laptop / desktop / mobile; requests sent to the load balancer.
  2. Load Balancer — distributes incoming requests; handles many users, improves availability, prevents overloading, supports scalability.
  3. App Engine Front End — receives requests from the load balancer, processes web / mobile requests, interacts with databases and storage, can use cache for faster response.
  4. Memcache — stores frequently accessed data temporarily in memory; faster access, fewer DB queries, better performance (e.g. product details, user session data).
  5. Cloud Storage (static) — images, videos, documents, backup files, CSS / JavaScript files.
  6. Datastore / Cloud SQL (dynamic) — Datastore = NoSQL, scalable, flexible; Cloud SQL = relational, SQL + structured tables. Stores user info, orders, transactions, app records.
  7. Task Queues — background / asynchronous tasks processed later instead of making the user wait (emails, image processing, report generation, data processing).
  8. Backend / Batch Application — processes background and batch jobs from the task queue (large datasets, reports, notifications, scheduled operations).
Memory hook: Client → LB → Front End → Memcache → Storage/DB → Queue → Backend.
C. Applications
  • Web applications
  • Mobile backends
  • APIs
  • E-commerce websites
  • Educational portals
5 Event-Driven Programs with Cloud Functions
A. Definition
  • Google Cloud Functions is a Function as a Service (FaaS) platform that executes code automatically in response to events.
  • Developers write only the function, while Google manages the infrastructure.
  • Event-Driven Computing: an application responds whenever an event occurs.
B. Common events
  • File uploaded to Cloud Storage
  • HTTP request
  • Database update
  • Firebase event
  • Cloud Scheduler event
C. Characteristics & advantages

Characteristics

  • Serverless
  • Automatic scaling
  • Pay only when executed
  • Supports multiple languages
  • Fast deployment

Advantages

  • No infrastructure management
  • Cost-effective
  • Highly scalable
  • Suitable for event processing
  • Easy integration with Google Cloud services
D. Applications & limitations

Applications

  • Image processing
  • Email notifications
  • IoT applications
  • Data validation
  • Log processing
  • API backends

Limitations

  • Limited execution time
  • Stateless execution
  • Cold start latency
  • Less suitable for long-running tasks
Memory hook: Event → Function → Auto-scale → Pay-per-run (Serverless).
6 Containers & GKE
A. What is containerization?

Packages an application together with its:

  • Application code
  • Required libraries
  • Dependencies
  • Runtime environment

→ into a lightweight unit called a container.

  • Most popular container platform: Docker.

Benefits

  • Portability
  • Fast startup
  • Consistent environments
  • Efficient resource utilization
  • Easy deployment
B. Features of GKE
  • Managed Kubernetes
  • Automatic upgrades
  • Auto repair
  • Auto scaling
  • Load balancing
  • Monitoring
  • Logging
  • Rolling updates
  • Self-healing
C. Key concepts
  • Container — a packaged application with its dependencies.
  • Pod — the smallest deployable unit in Kubernetes; can contain one or more containers.
  • Node — a virtual machine or worker machine that runs pods.
  • Cluster — a collection of nodes managed by Kubernetes.
  • SRE — Site Reliability Engineering.
  • SRE monitoring — continuously monitoring the health, performance, availability and reliability of Kubernetes clusters, nodes, pods, containers, applications, and network and storage resources.
Memory hook: Container → Pod → Node → Cluster (Managed Kubernetes).
D. Summary of the three Google services
  • Google App Engine (PaaS) — simplifies application deployment by abstracting infrastructure management; ideal for web apps and APIs.
  • Google Cloud Functions (FaaS) — executes code in response to events; well-suited for serverless, event-driven workloads.
  • Google Kubernetes Engine (GKE) — managed Kubernetes environment for deploying, scaling and orchestrating containerized applications with high flexibility and control.
7 SaaS · Docker · Linking
A. SaaS architecture — 4 layers
  1. Users — multiple customers accessing SaaS applications through the Internet.
  2. Client UI — interface through which users interact with the SaaS application: web browser, mobile application, desktop application. The user does not manage underlying servers or infrastructure.
  3. SaaS Orchestration — coordination and management layer: manages user requests, coordinates SaaS services, integrates multiple applications, controls workflows, delivers the required service to users.
  4. Cloud Servers — provide the actual computing infrastructure: processing power, storage, networking and application execution. The SaaS services run on these cloud resources.
B. Docker flow
  • Docker is a platform used to package an application and all its required dependencies into a lightweight unit called a container.
  • Helps developers build an application once and run it consistently on different cloud environments.
Build→ Package→ Store→ Deploy→ Run→ Scale
  1. Build the application.
  2. Package it into a Docker image.
  3. Store the image in a container registry.
  4. Deploy it to the cloud or Kubernetes.
  5. Run it as one or more containers.
  6. Scale containers based on user demand.
Memory hook: Build → Package → Store → Deploy → Run → Scale.
C. Docker orchestration
  • Automated management of multiple Docker containers across one or more servers.

Features / advantages

  • Automatic deployment
  • Automatic scaling
  • Auto restart
  • Load balancing
  • Auto scaling
  • Fault tolerance
  • High availability
  • Self-healing containers
  • Easy cluster management
  • Easy updates
D. Legacy linking of containers
  • Older Docker mechanism used to allow one container to communicate with another.
  • Has been deprecated and replaced by Docker networking.

Limitations

  • Deprecated feature
  • Difficult to scale
  • Manual linking
  • Static configuration
  • Not suitable for microservices
  • Limited flexibility
E. Dynamic linking + comparison
  • Containers communicate dynamically using Docker networking and service discovery rather than fixed IP addresses.

Containers locate services using

  • Container names
  • Docker DNS
  • Docker Compose service names
  • Kubernetes Services

Advantages

  • Automatic service discovery
  • Easy scaling
  • Flexible networking
  • Containers can restart without breaking communication
  • Simplifies microservices deployment

8 GCP Tooling
A. Understanding GCP projects

Project lifecycle

  1. Create Project
  2. Enable APIs
  3. Add Resources
  4. Assign IAM Roles
  5. Monitor Usage
  6. Delete Project (if no longer needed)

Benefits

  • Resource isolation
  • Separate billing
  • Better security
  • Easier collaboration
  • Access control using IAM
Memory hook: Create → Enable APIs → Add Resources → IAM → Monitor → Delete.
B. The GCP Console
  • User-friendly web interface for managing GCP.

Features

  • Create and manage Virtual Machines (VMs)
  • Deploy applications
  • Configure networking and security
  • Monitor resource usage
  • Manage storage and databases
  • View billing reports
  • Access IAM (Identity and Access Management)
  • Monitor logs using Cloud Logging

Advantages

  • Easy to use
  • No command-line knowledge required
  • Centralized management
  • Real-time monitoring
  • Secure access with Google accounts
C. Billing in GCP
  • Process of tracking and paying for the cloud resources and services used within projects.
  • Billing Account — linked to one or more GCP projects and contains the payment information.
Billing workflow: Track usage → Map to resources → Apply pricing → Generate invoice → Charge payment account
D. Cloud SDK
  • Collection of command-line tools that allow users to manage GCP resources from a terminal or command prompt.
  • Primary tool is gcloud, used to create, manage and monitor GCP resources.

Components

  • gcloud — main command-line interface for managing GCP services.
  • gsutil — manages Cloud Storage buckets and objects.
  • bq — manages BigQuery datasets and queries.
  • Local Emulator tools — for testing applications locally.

System requirements

  • Windows 10/11, Linux or macOS
  • Python (included with recent SDK versions or installed separately)
  • Internet connection
  • Google Cloud account

Installation steps

  1. Download Cloud SDK — visit the Google Cloud SDK download page and download the installer for your OS.
  2. Install — run the installer, follow the installation wizard, select the required components.
  3. Initialize the SDK — open Terminal (Linux / macOS) or Command Prompt (Windows) and run gcloud init.

Advantages

  • Fast resource management
  • Automation through scripts
  • Supports all GCP services
  • Easy deployment and administration
E. Cloud Shell
  • Browser-based command-line environment provided by Google Cloud.
  • Comes pre-installed with the Cloud SDK and other development tools — no local installation required.

Features / advantages

  • Browser-based terminal
  • Pre-installed Cloud SDK
  • Persistent home directory (5 GB storage)
  • Built-in code editor
  • Secure authentication
  • Access from anywhere

Limitations

  • Requires internet connectivity
  • Session timeout after inactivity
  • Limited persistent storage

Steps to use

  1. Log in to Google Cloud Console.
  2. Click the Cloud Shell icon (terminal icon).
  3. Wait for the environment to start.
  4. Execute GCP commands.
F. Google Cloud Platform APIs
  • Application programming interfaces that allow applications, scripts and users to interact programmatically with Google Cloud services.
  • Each Google Cloud service (Compute Engine, Cloud Storage, BigQuery, Cloud SQL) provides its own API.

Why use APIs?

  • Automate cloud operations
  • Manage resources programmatically
  • Integrate applications with GCP
  • Build cloud-native applications
APIPurpose
Compute Engine APIManage virtual machines
Cloud Storage APIManage storage buckets and files
Cloud SQL Admin APIManage SQL databases
BigQuery APIExecute data analytics queries
Kubernetes Engine APIManage Kubernetes clusters
Cloud Functions APIDeploy and manage serverless functions

Advantages of GCP APIs

  • Easy automation
  • High scalability
  • Secure authentication
  • Supports REST and client libraries
  • Integration with third-party applications
Memory hook: Console (UI) → SDK (CLI) → Shell (Browser) → APIs (Programmatic).
