1 Service Level Agreements
A. What is an SLA?
  • A formal contract between a Cloud Service Provider (CSP) and a customer.
  • Defines the expected level of service, performance standards, responsibilities, and remedies if the agreed service levels are not met.
  • Ensures customers know what level of service they can expect and how service quality will be measured.
B. Objectives of an SLA
  • Define the quality of service (QoS).
  • Guarantee service availability and reliability.
  • Specify performance expectations.
  • Clarify responsibilities of both provider and customer.
  • Establish penalties or compensation for service failures.
  • Build trust between provider and customer.
C. Types of SLAs
  1. Customer-Based SLA — designed for a specific customer; covers all services used by that customer.
    • Example: a university signs an SLA with Google Cloud for hosting its student portal.
  2. Service-Based SLA — applies to all customers using the same cloud service; same terms for everyone.
    • Example: an email hosting service guarantees 99.9% uptime to all users.
  3. Multi-Level SLA — different service levels defined for different users.
    • Corporate Level
    • Customer Level
    • Service Level
Memory hook: Customer-based = one customer · Service-based = all users · Multi-level = layered by audience.
D. Benefits of SLAs
  • Clearly defines expectations.
  • Improves service reliability.
  • Ensures accountability.
  • Enhances customer satisfaction.
  • Facilitates risk management.
  • Provides compensation for service failures.
  • Helps maintain business continuity.
2 Billing & Accounting
A. Definitions
  • Billing — process of calculating charges based on resource consumption.
  • Accounting — process of recording, tracking and reporting resource usage for auditing, budgeting and cost analysis.
  • Billing and accounting help cloud providers measure resource usage, calculate costs, generate invoices and monitor customer spending.
  • Providers typically use a Pay-as-You-Go (PAYG) model — customers pay only for the resources they use.
  • Billing covers cloud services such as virtual machines, storage, databases, networking and other managed services.
B. Objectives of billing
  • Calculate usage costs accurately.
  • Generate invoices for customers.
  • Support multiple pricing models.
  • Ensure transparent pricing.
  • Track customer expenses.
  • Enable cost optimization.
C. Billing models
  1. Pay-as-You-Go (PAYG) — pay only for resources actually used; no upfront investment. Example: paying ₹8 per hour for a virtual machine.
  2. Subscription-Based Billing — fixed monthly or yearly payment; suitable for predictable workloads.
  3. Reserved Instance Billing — customer reserves resources for a long period; lower cost than on-demand usage.
  4. Spot Pricing — uses unused cloud capacity; lowest price, but resources may be interrupted.
  5. Tiered Pricing — cost decreases as usage increases.
Memory hook: PAYG · Subscription · Reserved · Spot · Tiered.
3 Google Cloud Billing
A. What is Google Cloud Billing?
  • System used to track resource usage, calculate costs, generate invoices and manage payments for Google Cloud services.
  • Billing is linked to a Cloud Billing Account, which can be associated with one or more Google Cloud projects.
  • Google Cloud follows a Pay-as-You-Go (PAYG) pricing model — customers pay only for the resources they consume.
B. Features of GCP billing
  • Pay only for resources used.
  • Centralized billing account for multiple projects.
  • Cost tracking and usage reports.
  • Budget creation and alerts.
  • Billing export to BigQuery for detailed analysis.
  • Support for multiple payment methods.
  • Discounts such as Sustained Use Discounts and Committed Use Discounts.
C. Google Cloud billing models
  • Pay-as-You-Go (PAYG) — pay only for actual usage.
  • Committed Use Discounts (CUDs) — lower prices for long-term commitments.
  • Sustained Use Discounts (SUDs) — automatic discounts for continuous usage.
  • Free Tier — limited free usage for eligible services.
Memory hook: GCP billing = PAYG + CUDs + SUDs + Free Tier + BigQuery export.
4 Cloud Security & Shared Model
A. Introduction to cloud security
  • Collection of technologies, policies and controls that protect cloud-based applications, infrastructure and data from unauthorized access, cyberattacks and data loss.

Objectives of cloud security

  • Protect data confidentiality.
  • Maintain data integrity.
  • Ensure service availability.
  • Prevent unauthorized access.
  • Meet regulatory compliance requirements.
Memory hook: CIA + Access control + Compliance.
B. The Shared Responsibility Model
  • Defines how security responsibilities are divided between the Cloud Service Provider (Google Cloud) and the Customer.
Google secures… The cloud — physical infrastructure, data centers, hardware, core network, and the managed service foundations.
Customer secures… What is put in the cloud — data, applications, identities, access policies and configurations.
Memory hook: Google secures the cloud · you secure what's IN the cloud.
5 Encryption Options
A. Encryption at REST & in TRANSIT
  • Encryption protects data from unauthorized access by converting it into an unreadable format.

1. Encryption at REST

  • Data stored in Cloud Storage, Persistent Disks, Cloud SQL, etc. is encrypted automatically.
  • Google encrypts data before writing it to storage.

2. Encryption in TRANSIT

  • Data moving between users and Google Cloud services is protected using TLS (Transport Layer Security).
B. Customer-managed & supplied keys

3. Customer-Managed Encryption Keys (CMEK)

  • Customers manage encryption keys using Cloud Key Management Service (Cloud KMS).
  • Provides greater control over key rotation and access.

4. Customer-Supplied Encryption Keys (CSEK)

  • Customers provide their own encryption keys.
  • Google does not store these keys permanently.
Memory hook: REST = auto · TRANSIT = TLS · CMEK = you manage in KMS · CSEK = you supply, Google doesn't keep.
6 Cloud IAM
A. What is Cloud IAM?
  • Identity and Access Management controls who (identity) can access which resources and what actions they are allowed to perform.
B. Authentication
  • Verifies the identity of a user or service.

Examples

  • Username and password
  • Google Account
  • Service Account
  • Multi-Factor Authentication (MFA)
Question answered: Who are you?
C. Authorization
  • Determines what an authenticated user is allowed to do.

Examples

  • View resources
  • Create virtual machines
  • Delete storage buckets
  • Modify databases
Question answered: What are you allowed to do?
D. Best practices for authorization using Cloud IAM
  • Least privilege — grant only the permissions needed to perform a task.
  • Use predefined roles where possible; create custom roles only when necessary.
  • Prefer groups over individuals — assign roles to Google Groups rather than users.
  • Avoid primitive roles (Owner, Editor, Viewer) in production; use granular service-specific roles.
  • Use service accounts with scoped permissions for applications and automation.
  • Enable MFA for privileged accounts and audit access regularly.
  • Separate duties — do not give one identity both deployment and approval permissions.
  • Audit with Cloud Audit Logs — review who did what and when.
Memory hook: Least privilege + Groups + Service accounts + Granular roles + Audit logs.
7 Ansible — Configuration Management
A. Configuration management & Ansible
  • Configuration Management — process of automating the installation, configuration, deployment and maintenance of servers and applications.
  • Ensures all systems remain consistent, secure and correctly configured.
  • Ansible is an open-source configuration management, automation and orchestration tool developed by Red Hat.
  • Automates repetitive IT tasks such as software installation, system configuration, application deployment and server provisioning.
B. How Ansible works
Playbook→ Inventory→ SSH / WinRM→ Modules→ Status
  1. Administrator writes a playbook.
  2. Ansible reads the inventory file.
  3. Connects to managed nodes using SSH or WinRM.
  4. Executes tasks using modules.
  5. Reports the execution status.
C. Advantages
  • Open source and free.
  • Agentless architecture.
  • Easy to learn using YAML.
  • Fast deployment.
  • Supports Infrastructure as Code (IaC).
  • Scalable and highly reliable.
D. Limitations
  • SSH-based communication may be slower than agent-based tools for very large deployments.
  • Complex workflows may require advanced playbook design.
  • Less suitable for extremely large-scale environments without optimization.
Memory hook: Ansible = agentless + YAML + IaC + SSH + modules.
8 DevOps
A. What is DevOps?
  • Software development methodology that combines Development (Dev) and Operations (Ops).
  • Aims to improve collaboration, automate workflows and deliver software faster and more reliably.
  • Integrates development, testing, deployment, monitoring and feedback into a continuous lifecycle.
B. DevOps architecture lifecycle
Plan→ Code→ Build→ Test→ Release→ Deploy→ Monitor→ Feedback
  • Each stage feeds back into the next, forming a continuous loop.
  • Automation tools connect the stages end to end.
C. Benefits & challenges

Benefits

  • Faster software delivery.
  • Improved collaboration between development and operations teams.
  • Continuous integration and deployment.
  • Reduced deployment failures.
  • Faster recovery from incidents.
  • Better software quality.
  • Increased automation and efficiency.

Challenges

  • Cultural and organizational changes.
  • Initial setup complexity.
  • Tool integration challenges.
  • Security and compliance management.
  • Continuous monitoring and maintenance requirements.
D. Traditional IT vs DevOps
AspectTraditional ITDevOps
TeamsSeparate Development and Operations teamsCollaborative Dev and Ops teams
DeploymentsManual deploymentsAutomated deployments
ReleasesInfrequent software releasesFrequent and continuous releases
FeedbackSlow feedbackContinuous feedback
TestingManual testingAutomated testing
Release cyclesLonger release cyclesFaster release cycles
Memory hook: DevOps = Dev + Ops + CI/CD + Automation + Continuous feedback.
