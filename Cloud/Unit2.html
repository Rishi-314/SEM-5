1 Basics & Approaches
A. What is virtualization?
  • The ability to run multiple operating systems on a single physical system and share the underlying hardware resources.
  • Can be viewed as utility computing — computing power seen as a utility clients pay for only as needed.
  • Usual goal: centralize administrative tasks while improving scalability and workloads.

Formal definition

  • A technique for hiding the physical characteristics of computing resources from the way other systems, applications or end users interact with those resources.
  • Makes a single physical resource (server, OS, application, storage device) appear as multiple logical resources.
  • OR makes multiple physical resources (storage devices, servers) appear as a single logical resource.
B. Virtual machine concept
  • A machine with virtualization software can host numerous applications, including those that run on different operating systems, on a single platform.
  • The host operating system supports a number of virtual machines, each with the characteristics of a particular OS.
  • The solution enabling virtualization is a Virtual Machine Monitor (VMM), or hypervisor.

C. Simple example & user's view
  • Example: dividing an actual hard drive into different partitions — logical division of a disk to create two or more separate drives (C:, D:, E:).
  • User's view involves SAN (Storage Area Network) and NAS (Network Attached Storage).
D. Why virtualization? (benefits & reality)

Motivations

  • Cost reduction
  • Isolation and creating a protected environment
  • Testing and evaluation of OS, kernel or application
  • Ease of duplication
  • Relocation (and disaster recovery)
  • Running an application not supported by the host
  • Green IT

The reality

  • Most servers use only 5–15% of their capabilities on average, while consuming 60–90% of their peak power.
  • Solution: use one server to host multiple applications → reduce energy consumption and CO₂ emissions.

Virtualization benefits

  • Reduce real estate needs
  • Increase up time
  • Reduce CO₂ emissions, power and cooling requirements
  • Increase flexibility
  • Reduce overall costs
Memory hook: Virtualization = many OSs on one box · idle servers 5–15% → consolidate → Green IT.

2 Hypervisors
A. What is a hypervisor?
  • Runs above the supervisor mode and itself runs in supervisor mode.
  • Recreates a hardware environment.
  • Piece of software that enables us to run one or more VMs on a physical server (host).

Two major types: Type-I and Type-II.

B. Type-I Hypervisor (bare-metal)
  • Runs directly on hardware — no host OS required.
  • High performance with minimal overhead.
  • Strong isolation between virtual machines.
  • Efficient resource allocation.
  • Highly scalable for enterprise and cloud environments.

Limitations

  • Requires dedicated hardware.
  • More complex to install and manage than Type-II.
  • Enterprise editions may involve licensing costs.
  • Hardware compatibility must be verified.

C. Type-II Hypervisor (hosted)
  • Also called a hosted hypervisor.
  • Runs on top of an existing operating system (host OS) rather than directly on hardware.
  • Programs managed by the OS.
  • Supports multiple guest operating systems simultaneously.
  • Hardware access is managed through the host operating system.

3 Compute Options in the Cloud
A. Virtual Machines
  • Full control over the infrastructure.
  • Provides virtualized computing resources over the Internet.
  • Users have full control over OS, storage and applications.
  • Suitable for hosting websites, enterprise applications, databases and development environments.
  • Examples: AWS EC2, Microsoft Azure Virtual Machines, Google Cloud Compute Engine.
B. Containers
  • Packages applications with all dependencies.
  • Lightweight and portable.
  • Faster startup than virtual machines.
  • Best for microservices and cloud-native applications.
  • Examples: Docker, Kubernetes, Google Kubernetes Engine (GKE), Azure Kubernetes Service (AKS).
C. Serverless & PaaS

Serverless

  • Developers write functions without managing servers.
  • Cloud provider automatically handles scaling and infrastructure.
  • Users pay only for execution time.
  • Suitable for event-driven applications, APIs and automation.
  • Examples: AWS Lambda, Azure Functions, Google Cloud Functions.

PaaS — managed environment for application development.

D. Bare Metal, Batch & HPC

Bare Metal

  • Dedicated physical hardware for a single customer.
  • No virtualization overhead.
  • Used for HPC, gaming and large databases.

Batch Computing

  • Large-scale automated job execution without manual intervention.
  • Suitable for scientific simulations, financial analysis and data processing.

HPC (High-Performance Computing)

  • Uses clusters of powerful computers to solve complex computational problems.
  • Applications: weather forecasting, AI training, engineering simulations, genomics.
Memory hook: VM → Containers → Serverless → PaaS → Bare Metal → Batch → HPC.
4 Elastic Apps & Auto Scaling
A. Elastic applications
  • Cloud applications that automatically increase or decrease computing resources (VMs, containers or instances) based on workload demand.
  • Helps maintain performance while minimizing costs.
  • Driven by predefined policies or real-time metrics — CPU usage, memory utilization, network traffic, number of user requests.
B. Objectives
  • Maintain high application performance.
  • Handle sudden traffic spikes.
  • Reduce infrastructure costs by removing unused resources.
  • Ensure high availability and fault tolerance.
C. Components of auto scaling
  1. Application — the web application or service running in the cloud.
  2. Load Balancer — distributes incoming requests evenly across multiple instances.
  3. Auto Scaling Group — manages the minimum, maximum and desired number of instances.
  4. Monitoring Service — continuously monitors metrics such as CPU utilization, memory usage and network traffic.
  5. Scaling Policies — define when to add or remove instances based on thresholds.
Memory hook: App + Load Balancer + Auto Scaling Group + Monitoring + Scaling Policies.
5 VMware · Xen · KVM · EC2
A. Vendors & projects
  • VMware — founded 1998, Palo Alto, California; majority owned by EMC Corporation; implements both Type-1 and Type-2 VMs.
  • Xen — first developed at the University of Cambridge Computer Laboratory; community-maintained as free software under GPLv2 (as of 2010); implements para-virtualization.
  • KVM (Kernel-based Virtual Machine) — a Linux kernel virtualization infrastructure; supports native virtualization using Intel VT-x or AMD-V (as of 2010).
B. VMware — basic properties
  • Separates OS and hardware — breaks hardware dependencies.
  • OS and application as a single unit by encapsulation.
  • Strong fault and security isolation.
  • Standard, hardware-independent environments can be provisioned anywhere.
  • Flexibility to choose the right OS for the right application.
C. Xen — properties & features

Basic properties

  • Para-virtualization.
  • Achieves high performance even on its host architecture (x86), which is known to be non-cooperative with traditional virtualization.
  • Hardware-assisted virtualization — Intel and AMD contributed modifications to Xen for Intel VT-x and AMD-V extensions.
  • Live migration — the LAN iteratively copies the VM memory to the destination without stopping its execution.

Implemented in: Novell SUSE Linux Enterprise 10, Red Hat RHEL 5, Sun Solaris.

Hardware assistance in Xen

  • CPU provides VMExit for certain privileged instructions.
  • Extended page tables used to virtualize memory.

Xen features

  • Guest OS runs without modification (e.g. legacy Linux and Windows).
  • Simple platform emulation: BIOS, APIC, IOAPIC, RTC, Net (pcnet32), IDE emulation.
  • Para-virtualized drivers installed after booting for high-performance I/O.
  • Possibility of CPU and memory para-virtualization.
  • Non-invasive hypervisor hints from the OS.
D. KVM — full virtualization
  • Linux host OS; kernel component included in mainline Linux since 2.6.20.
  • Full virtualization for Linux on x86 hardware with Intel VT or AMD-V extensions.
  • Can run multiple VMs with unmodified Linux or Windows images.

Components

  • kvm.ko — loadable kernel module providing core virtualization infrastructure.
  • kvm-intel.ko / kvm-amd.ko — processor-specific modules.

I/O device model in KVM

  • Requires a modified QEMU for the I/O virtualization framework.
  • Guest hardware accesses are intercepted by KVM; QEMU emulates hardware behavior of common devices: RTL 8139, PIIX4 IDE, Cirrus Logic VGA.
  • I/O performance improved by the virtio para-virtualization framework.
Memory hook: VMware = both types · Xen = para + live migration · KVM = Linux mainline + full virt + QEMU/virtio.
E. Amazon EC2 — key features
  • Elastic Scaling — increase or decrease instances based on demand; supports Auto Scaling.
  • Virtual Servers (Instances) — launch VMs with different CPU, memory, storage and networking configurations.
  • Pay-as-You-Go Pricing — pay only for compute resources used; no upfront hardware investment.
  • Multiple Operating Systems — Linux, Windows, Ubuntu, Red Hat, SUSE and others.
  • High Availability — deploy across multiple Availability Zones; integrates with Elastic Load Balancing (ELB).
  • Security — Security Groups (virtual firewalls) and AWS IAM integration.
  • Storage Support — attach Amazon Elastic Block Store (EBS) volumes; supports instance storage for temporary data.
  • Monitoring — Amazon CloudWatch monitors CPU usage, memory, network traffic and disk performance.
Memory hook: EC2 = Elastic + Instances + Pay-as-you-go + Multi-OS + AZs + IAM + EBS + CloudWatch.
6 Memory Virtualization
A. What it is
  • Process of creating a virtual view of memory for each VM.
  • The hypervisor maps guest virtual memory used by the VM to the actual physical memory of the host.
  • Allows multiple VMs to share the same physical RAM securely and efficiently.

Flow

  1. Application requests memory from the Guest OS.
  2. Guest OS allocates Guest Virtual Memory.
  3. Hypervisor translates guest memory addresses into host physical memory addresses.
  4. Data is stored or retrieved from the host's physical RAM.
  5. Multiple VMs safely share host memory while remaining isolated.
B. Ballooning
  • A balloon driver inside the guest OS releases unused memory back to the hypervisor.
  • Reclaimed memory can be assigned to other virtual machines.

Advantages

  • Efficient memory utilization.
  • Allows dynamic memory allocation.

Disadvantages

  • May reduce VM performance if excessive memory is reclaimed.
Memory hook: Ballooning = guest gives back idle RAM → hypervisor reuses it.
C. Deduplication & sharing
Before: VM1 → Page A · VM2 → Page A · VM3 → Page A  (3 copies in RAM)
After: VM1, VM2, VM3 → Shared Page A  (only 1 copy in RAM)

Advantages

  • Reduces physical memory usage.
  • Increases the number of VMs that can run on a host.
  • Improves hardware utilization and lowers infrastructure costs.
  • Reduces power consumption and improves virtualization efficiency.

Disadvantages

  • Hypervisor scanning consumes CPU resources.
  • Limited benefit when VMs have mostly unique or encrypted memory pages.
  • Potential security concerns if not properly implemented.
  • Memory savings vary with workload similarity.
Memory hook: Deduplication = many VMs, one copy of an identical page.
7 Network & Storage Virtualization
A. Network virtualization — definition
  • Process of creating virtual networks by abstracting physical network resources.
  • Enables multiple VMs or containers to communicate over isolated virtual networks while sharing the same physical infrastructure.
B. Components
  • Virtual Network Interface (vNIC) — connects a VM to the virtual network.
  • Virtual Switch (vSwitch) — connects VMs on the same host.
  • Virtual Router — routes traffic between virtual networks.
  • Software-Defined Networking (SDN) — centrally manages network configuration and traffic.
  • Virtual Firewall — protects virtual networks from unauthorized access.
C. Advantages
  • Better network utilization.
  • Easy network configuration and management.
  • Improved scalability.
  • Enhanced security through network isolation.
  • Supports live migration of VMs.
Memory hook: Network virt = vNIC + vSwitch + vRouter + SDN + vFirewall.
8 Migration & Replication
A. VM migration & types
  • Process of moving a VM from one physical host to another with minimal or no interruption to running applications.
  • Used for load balancing, maintenance, fault tolerance and energy efficiency.

Types

  • Live Migration — VM continues running during migration with minimal downtime.
  • Cold (Offline) Migration — VM is powered off before migration, resulting in longer downtime.
B. Replication & benefits
  • Creating and maintaining an exact copy of a VM on another server or data center.
  • The replica can be used for backup, disaster recovery and high availability.

Benefits

  • Disaster recovery
  • High availability
  • Backup and restore
  • Fault tolerance
  • Business continuity
C. Pre-copy migration
  • VM's memory pages are copied from source to destination while the VM is still running.

Working steps

  1. Start the VM on the source host.
  2. Copy all memory pages to the destination.
  3. Track pages modified during copying (dirty pages).
  4. Re-copy the dirty pages in several iterations.
  5. Pause the VM briefly.
  6. Transfer the remaining dirty pages and CPU state.
  7. Resume the VM on the destination host.
Source: VM Running ──► Copy Memory Pages ──► Destination
Dirty Pages ──► Pause VM ──► Re-copy Dirty Pages ──► Transfer CPU State ──► Resume VM

Advantages: very short downtime; widely used in cloud; suitable for high-availability apps.

Disadvantages: multiple transfers of dirty pages increase network traffic; migration may take longer if memory changes rapidly.

D. Post-copy migration
  • VM is first suspended, CPU state is transferred to the destination, and the VM resumes there immediately.
  • Remaining memory pages are fetched from the source host on demand.

Working steps

  1. Pause the VM on the source host.
  2. Transfer the CPU state to the destination.
  3. Resume the VM at the destination.
  4. Memory pages are fetched from the source whenever needed (page faults).
  5. Remaining pages are copied in the background.
Source: Pause VM ──► Transfer CPU State ──► Destination VM Starts
Memory Pages ◄── On-Demand Pages ──► Background Copy

Advantages: each page transferred only once; faster total migration time; lower network bandwidth.

Disadvantages: more page faults after migration; if the source host fails before completion, the VM may fail.

E. Pre-copy vs Post-copy — comparison
AspectPre-CopyPost-Copy
When memory movesBefore VM resumes; while runningAfter VM resumes; on demand
DowntimeVery short pause at the endVery short pause at the start
Page transfersDirty pages re-copied in iterationsEach page transferred only once
Network usageHigher (repeated dirty pages)Lower
Total timeLonger if memory changes rapidlyFaster
RiskLowSource failure can break the VM
Memory hook: Pre-copy = copy first, pause last · Post-copy = pause first, fetch later.
