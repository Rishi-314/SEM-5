1 Introduction & Definitions
A. Origin of the name
  • The name cloud computing was inspired by the cloud symbol often used to represent the Internet in flowcharts and diagrams.
  • Cloud computing is a general term for anything that involves delivering hosted services over the Internet.
B. What is Cloud Computing?
  • Internet-based computing — large groups of remote servers are networked.
  • Sharing of data-processing tasks, centralized data storage, computer services and resources.
  • Any computer-related task done entirely on the Internet.
  • Allows users to use software without owning the hardware.
  • Everything is done remotely — nothing is saved locally.
C. Cloud computing components
  • Network — connects users, applications and data to the cloud.
  • Without a network:
    • Users cannot access their cloud services.
    • Applications, data and users cannot move between clouds.
  • Infrastructure components must work together to create a cloud.
D. Attributes of cloud networking
  • Scalability — the cloud network must scale to the overall throughput level so it does not become a bottleneck.
  • Low Latency — must deliver microsecond latency across the entire network fabric; improves application performance and server utilization.
  • Guaranteed Performance — predictable performance for many simultaneous applications including video, voice and web traffic.
  • Extensible Management — real-time upgrades and image/patch management across a large cloud network.
  • Self-Healing Resilience — cloud networks run 24×7, so downtime is not an option; requires self-healing and transparent in-service software updates.
Memory hook: Cloud network = Scalable + Low-latency + Guaranteed + Extensible + Self-healing.
2 Central Ideas & Characteristics
A. What cloud computing really is
  • Cloud computing is a paradigm of computing — a new way of thinking about the IT industry, not any specific technology.
Central ideas: Utility Computing · SOA · SLA.
B. Central ideas explained
  • Utility Computing — computing resources delivered as a metered, pay-per-use service.
  • SOA (Service-Oriented Architecture) — building applications from independent, reusable, interoperable services.
  • SLA (Service Level Agreement) — a contract defining the guaranteed level of service between provider and consumer.
C. Properties and characteristics
  • High scalability and elasticity
  • High availability and reliability
  • High manageability and interoperability
  • High accessibility and portability
  • High performance and optimization
D. Enabling techniques
  • Hardware virtualization — abstracting logical resources from physical hardware.
  • Parallelized and distributed computing — splitting work across many machines.
  • Web service — standardized interfaces for app-to-app communication over the Internet.
Memory hook: Characteristics — Scale · Available · Manageable · Accessible · Performant.
3 Cluster vs Distributed Computing
A. Cluster computing

Focuses on:

  • High performance
  • Parallel processing
  • Fault tolerance

Structure

  • Nodes are typically centralized, located in the same physical space.
  • Run identical or similar hardware/software configurations.

Key mechanisms

  • High-speed, low-latency network interconnects (e.g. InfiniBand).
  • Built-in failover — if one node drops, another immediately takes over its workload.
B. Distributed computing
  • A much broader network of independent systems.
  • May span different geographies and network infrastructures.

Structure

  • Nodes are often heterogeneous — different hardware, operating systems and resources.
  • Operate on public networks like the Internet.

Key mechanisms

  • Nodes do not act as one single computer.
  • Collaborate by passing messages to coordinate activities.
  • Designed to scale infinitely and gracefully handle partial system failures without bringing the entire network down.
C. Cluster vs Distributed — comparison

4 Evolution of Cloud Computing
A. Eight stages of evolution
Mainframe→ PC→ Client-Server→ Distributed→ Grid→ Utility→ Virtualization→ Cloud
B. Stages 1–4
  1. Mainframe Computing (1950s–1960s)
    • Large, centralized computers used by multiple users.
    • Users accessed the mainframe through dumb terminals.
    • Computing resources were expensive and shared.
    • Example: IBM Mainframe Systems.
  2. Personal Computing (1980s)
    • Introduction of affordable personal computers (PCs).
    • Computing became decentralized.
    • Software installed and executed on individual machines.
    • Example: IBM PC, Apple Macintosh.
  3. Client-Server Computing (1990s)
    • Applications divided between client computers and central servers.
    • Improved resource sharing and data management.
    • Commonly used for databases and enterprise applications.
    • Example: web browsers communicating with web servers.
  4. Distributed Computing (1990s–2000s)
    • Multiple computers worked together to solve complex problems.
    • Improved performance, reliability and fault tolerance.
    • Includes Grid Computing and Cluster Computing.
C. Stages 5–8
  1. Grid Computing (late 1990s)
    • Resources from multiple geographically distributed computers were combined.
    • Suitable for scientific research and large-scale computations.
    • Example: SETI@home.
  2. Utility Computing (early 2000s)
    • Computing resources provided as a metered service.
    • Users paid only for resources consumed.
    • Introduced the Pay-as-you-Go model.
    • Laid the foundation for cloud computing.
  3. Virtualization (2000s)
    • Multiple virtual machines (VMs) run on a single physical server.
    • Improved hardware utilization and reduced infrastructure costs.
    • Enabled rapid provisioning and resource isolation.
    • Hypervisors: VMware ESXi, Xen, KVM.
  4. Cloud Computing (2006–present)
    • Computing resources delivered over the Internet on demand.
    • Resources automatically provisioned and scaled.
    • Users pay only for actual usage.
    • Major providers: Google Cloud Platform (GCP), Amazon Web Services (AWS), Microsoft Azure.
Memory hook: Mainframe → PC → Client-Server → Distributed → Grid → Utility → Virtualization → Cloud.

A. Cloud storage vs traditional storage

B. Architecture note & the Inter-cloud
  • The software systems involved in delivery communicate over a loose coupling mechanism.
  • Inter-cloud — an interconnected global “cloud of clouds” and an extension of the Internet.
Memory hook: Cloud = provider-managed · Traditional = you-manage.
6 Cloud & Google Cloud Architecture
A. Cloud architecture — basic layers
SaaS — Software
PaaS — Platform
IaaS — Infrastructure
  • Software systems involved in delivery communicate over a loose coupling mechanism.
  • Inter-cloud — interconnected global “cloud of clouds”, an extension of the Internet.
B. Google Cloud — core architectural pillars
  • Operational Excellence — automated deployment pipelines and robust monitoring.
  • Security & Compliance — identity management and encryption to protect sensitive data.
  • Reliability & Performance — built-in redundancy and auto-scaling spanning compute engines and serverless components.
  • Cost Optimization — tools to evaluate active vs. archival storage and budget controls to manage resources efficiently.
C. Deployment archetypes (6)
  1. Zonal — runs in a single zone to minimize latency, but vulnerable to localized failures.
  2. Regional — operates across multiple zones within a single region for fault tolerance.
  3. Multi-Regional — spans multiple zones across two or more regions.
  4. Global — distributed across regions worldwide.
  5. Hybrid — connects Google Cloud resources with on-premises data centers.
  6. Multicloud — integrates workloads between Google Cloud and other cloud providers (e.g. AWS, Azure).
Memory hook: Zonal → Regional → Multi-Regional → Global → Hybrid → Multicloud.
7 Service Models
A. Overview — IaaS / PaaS / SaaS
  • IaaS — users maintain software; rent IT infrastructure (servers, storage, networking).
  • PaaS — users are given software and hardware automatically; rent a development platform to build and deploy apps.
  • SaaS — all software and hardware is transparent; the user only knows their own access point; rent software and use applications through a web browser.
SaaS — Software
PaaS — Platform
IaaS — Infrastructure
Memory hook: IaaS = Infrastructure · PaaS = Platform · SaaS = Software.
B. Infrastructure as a Service (IaaS)

Definition

  • Provision processing, storage, networks and other fundamental computing resources.
  • Consumer can deploy and run arbitrary software, including operating systems and applications.
  • Consumer does not manage the underlying cloud infrastructure but controls:
    • Operating systems
    • Storage
    • Deployed applications
    • Possibly limited control of select networking components

Examples: Amazon EC2, Eucalyptus, OpenNebula.

Enabling technique — Virtualization

  • Abstraction of logical resources away from underlying physical resources.
  • Shifts the OS onto a hypervisor; multiple OS share the physical hardware and provide different services.
  • Improves utilization, availability, security and convenience.

Properties supported by virtualization

  • Manageability and interoperability
  • Availability and reliability

C. IaaS — provided services

1. Resource Management Interface

  • Virtual Machine — creation, suspension, resumption, termination.
  • Virtual Storage — space allocation, space release, data writing, data reading.
  • Virtual Network — IP address allocation, domain name registration, connection establishment, bandwidth provision.

2. System Monitoring Interface

  • Virtual Machine — CPU loading, memory utilization, I/O loading, internal network loading.
  • Virtual Storage — virtual space utilization, data duplication, storage-device access bandwidth.
  • Virtual Network — virtual network bandwidth, network connectivity, network load balancing.
IaaS summary: deployment platform that abstracts infrastructure · enabling technique = virtualization (server, storage, network) · services = Resource Management + System Monitoring interfaces.
D. Platform as a Service (PaaS)

Definition

  • Deploy consumer-created or acquired applications built with provider-supported languages and tools.
  • Consumer does not manage the underlying infrastructure (network, servers, OS, storage).
  • Consumer controls deployed applications and possibly application-hosting-environment configurations.

Examples: Microsoft Windows Azure, Google App Engine, Hadoop.

Enabling technique — Runtime Environment Design

  • Collection of software services available to applications; usually implemented by program libraries.
  • Common properties: manageability & interoperability, performance & optimization, availability & reliability, scalability & elasticity.
E. PaaS — provided services

1. Programming IDE

  • Users develop their service using the IDE.
  • IDE must integrate full functionalities supported by the underlying runtime environment.
  • IDE provides development tools: profiler, debugger, testing environment.
  • Programming APIs vary between providers but share common operating functions: computation, storage and communication resource operations.

2. System Control Interface

  • Policy-Based Control — a principle or rule to guide decisions and achieve a rational outcome; makes decisions according to requirements.
  • Workflow Control — describes the flow of installation and configuration of resources; a workflow-processing daemon delivers speedy, efficient construction and management of cloud resources.
PaaS summary: development platform abstracting infrastructure, OS and middleware to drive developer productivity · enabling technique = runtime environment · services = Programming IDE + System Control Interface.
F. Software as a Service (SaaS)

Definition

  • Use the provider's applications running on cloud infrastructure.
  • Accessible from various client devices through a thin-client interface such as a web browser (e.g. web-based email).
  • Consumer does not manage the underlying infrastructure — network, servers, OS, storage or even individual application capabilities — with the possible exception of limited user-specific configuration settings.

Examples: Google Apps (Gmail, Google Docs, Google Sites), SalesForce.com, EyeOS.

Enabling technique — Web Service / Web 2.0

  • Viewing the Internet as a computing platform.
  • Running interactive applications through a web browser.
  • Leveraging interconnectivity and mobility of devices.
  • Enhanced effectiveness with greater human participation.
  • Internet provides: accessibility and portability.
G. SaaS — provided services

1. Web-based Applications — conventional applications translate their access interface onto a web platform.

  • General Applications — office suite, multimedia, instant messaging.
  • Business Applications — ERP, CRM, market trading system.
  • Scientific Applications — aerospace simulation, biochemistry simulation.
  • Government Applications — national medical system, public transportation system service.

2. Web Portal

  • Beyond search, offers email, news, stock prices, information, databases and entertainment.
  • Provides a consistent look and feel with access control and procedures for multiple applications and databases.
  • Examples: iGoogle, MSNBC, Netvibes, Yahoo!
SaaS summary: finished applications that you rent and customize · enabling technique = web service · services = Web-based Applications + Web Portal.
8 Deployment Models
A. Four primary models
  • Public cloud — done by service providers.
  • Community cloud — organizations from a specific community with common concerns.
  • Private cloud — operated solely for a single organization.
  • Hybrid cloud — composition of two or more clouds (private, community or public).
  • Private cloud rentals — an option to consider when security is a concern.

All can exhibit the same characteristics; differences lie primarily in the scope and access of published cloud services.

B. Public cloud

Definition

  • Infrastructure made available to the general public or a large industry group.
  • Owned by an organization selling cloud services.
  • Also known as external cloud or multi-tenant cloud; openly accessible.

Basic characteristics

  • Homogeneous infrastructure
  • Common policies
  • Shared resources and multi-tenant
  • Leased or rented infrastructure
  • Economies of scale
C. Private cloud

Definition

  • Infrastructure operated solely for one organization.
  • May be managed by the organization or a third party.
  • May exist on-premise or off-premise.
  • Also called internal cloud or on-premise cloud; intentionally limits access to consumers of the same organization.

Basic characteristics

  • Heterogeneous infrastructure
  • Customized and tailored policies
  • Dedicated resources
  • In-house infrastructure
  • End-to-end control
D. Public vs Private — comparison
AspectPublic CloudPrivate Cloud

E. Community & Hybrid cloud

Community cloud

  • Infrastructure shared by several organizations.
  • Supports a specific community with shared concerns — mission, security requirements, policy and compliance considerations.

Hybrid cloud

  • Composition of two or more clouds (private, community or public).
  • Clouds remain unique entities but are bound together by standardized or proprietary technology.
  • Enables data and application portability.
  • Example: cloud bursting for load-balancing between clouds.
Memory hook: Public = shared/external · Private = dedicated/internal · Community = shared concerns · Hybrid = two or more clouds.
