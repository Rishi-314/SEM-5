1 Introduction to Cloud Networking
A. What is cloud networking?
  • The practice of designing, configuring and managing network infrastructure within a cloud computing environment.
  • Enables communication between cloud resources (virtual machines, containers, databases, storage) and external users over secure, scalable and high-performance networks.
  • Replaces or extends traditional physical networking using software-defined technologies, allowing flexible and cost-effective network infrastructures.
Memory hook: Cloud networking = software-defined networking inside a cloud.
B. Objectives
  • Connect cloud resources securely.
  • Enable communication between applications and services.
  • Provide high availability and reliability.
  • Support scalability and flexibility.
  • Ensure secure access to cloud resources.
  • Optimize network performance and reduce latency.
C. Advantages
  • Scalability on demand.
  • High availability and reliability.
  • Centralized network management.
  • Improved security with firewalls and IAM.
  • Cost-effective — pay for what you use.
  • Faster deployment and easier maintenance.
D. Challenges
  • Security threats such as cyberattacks.
  • Network latency for geographically distant users.
  • Complexity in hybrid and multi-cloud environments.
  • Vendor-specific networking features.
  • Dependence on Internet connectivity.
E. Types of cloud networks
  1. Public Cloud Network — infrastructure owned and managed by a cloud provider; accessible over the Internet. Examples: GCP, AWS, Microsoft Azure.
  2. Private Cloud Network — dedicated to a single organization; greater control, privacy and security.
  3. Hybrid Cloud Network — combines private and public cloud environments; enables workload and data sharing between them.
  4. Multi-Cloud Network — uses services from multiple cloud providers; improves flexibility and reduces vendor lock-in.
Memory hook: Public · Private · Hybrid · Multi-Cloud.
2 IP Address Basics
A. What is an IP address?
  • A unique numerical identifier assigned to every device connected to a network.
  • Enables devices to communicate by identifying the source and destination of data packets.
  • Works like a postal address — just as a postal address delivers mail to the right house, an IP address delivers data to the right device.
B. Functions of an IP address
  • Identifies devices on a network.
  • Enables communication between devices.
  • Supports routing of data packets.
  • Helps locate the source and destination of network traffic.
C. Importance in cloud computing
  • Enables communication between cloud resources.
  • Supports virtual machine networking.
  • Allows secure Internet access.
  • Facilitates routing and load balancing.
  • Supports hybrid and multi-cloud connectivity.

3 Google's Network Architecture
A. Overview
  • GCP uses one of the world's largest private global fiber-optic networks, connecting data centres across the globe.
  • This infrastructure ensures high availability, low latency and secure communication.
B. Components
  • Regions — independent geographic locations containing multiple zones.
  • Zones — isolated data centers within a region where resources run.
  • Edge Locations (Points of Presence — PoPs) — bring services closer to users for faster access.
  • Global Private Backbone — Google's high-speed private network connecting all regions.
Edge PoP → Region (Zone · Zone · Zone) → Global Private Backbone → Region (Zone · Zone · Zone) → Edge PoP
C. Features
  • Global private fiber network.
  • High-speed connectivity.
  • Low latency.
  • High availability.
  • Automatic traffic optimization.
  • Secure communication.
Memory hook: Regions → Zones → Edge PoPs → Global Private Backbone.
4 Routes & Firewall Rules
A. Cloud routes — definition
  • A networking rule that determines the path or next hop for packets based on their destination IP address.
  • In Google Cloud, routes enable communication between VPC subnets and provide connectivity to external networks through gateways, VPN tunnels or other next hops.
B. Types of routes
  • System-generated Routes — automatically created for subnets.
  • Static Routes — manually configured by administrators.
  • Dynamic Routes — learned using Cloud Router and BGP.

Route components

  • Destination IP range
  • Next hop
  • Priority
  • Network tags (optional)
C. Firewall rules — definition
  • Security rules that control which network traffic is allowed or denied between cloud resources and other networks.
  • Control incoming (Ingress) and outgoing (Egress) traffic.
  • Based on parameters such as source, destination, protocol, port and target resources.
  • Help protect cloud resources from unauthorized network access.
D. How firewall rules work — 7 parameters
  • Direction — ingress or egress
  • Source — where traffic originates
  • Destination — where traffic is going
  • Protocol — TCP, UDP, ICMP, etc.
  • Port — e.g. 22, 80, 443
  • Target — which cloud resources the rule applies to
  • Action — allow or deny
E. Route vs Firewall — comparison
RouteFirewall
Determines where traffic goesDetermines whether traffic is allowed
Concerned with path selectionConcerned with security
Uses destination IP / routing infoUses source, destination, protocol, port, etc.
Example: send traffic through VPNExample: allow TCP port 443
Memory hook: Route = where · Firewall = whether.
5 Multiple VPC Networks
A. Overview
  • A project can contain multiple Virtual Private Cloud (VPC) networks to isolate workloads and improve security.
B. Types of VPC networks
  • Auto Mode VPC — automatically creates subnets in every region; suitable for beginners and small deployments.
  • Custom Mode VPC — user creates and manages subnets; greater flexibility and control.
  • Shared VPC — multiple projects share a centrally managed VPC; common in large organizations.
  • VPC Peering — connects two VPC networks privately; no traffic over the public Internet; low latency and high bandwidth.
Memory hook: Auto · Custom · Shared · Peered.
C. Benefits
  • Network isolation.
  • Improved security.
  • Simplified management.
  • Better scalability.
6 Building Hybrid Clouds
A. Overview
  • A hybrid cloud combines on-premises infrastructure with Google Cloud resources.
B. Cloud VPN
  • Creates a secure encrypted tunnel over the Internet.

Features

  • IPSec encryption
  • Secure communication
  • Easy deployment
  • Cost-effective
C. Cloud Interconnect
  • Provides dedicated private connectivity between on-premises networks and Google Cloud.

Types

  • Dedicated Interconnect — direct physical connection; high bandwidth (10–100 Gbps); suitable for large enterprises.
  • Partner Interconnect — connectivity through a supported service provider; flexible bandwidth options; easier deployment.
D. Direct Peering
  • Allows organizations to connect directly to Google's edge network.

Features

  • Lower latency
  • Improved network performance
  • Suitable for large Internet service providers and enterprises
E. Hybrid options — comparison

7 Load Balancing
A. Overview & benefits
  • A load balancer distributes incoming traffic across multiple servers to improve availability and performance.

Benefits

  • High availability
  • Fault tolerance
  • Better performance
  • Automatic scaling
B. Types of load balancers
  1. Global External HTTP(S) Load Balancer — Layer 7 (Application Layer); global traffic distribution; supports SSL termination.
  2. Regional External Application Load Balancer — Layer 7; regional traffic management.
  3. Internal Application Load Balancer — internal traffic distribution; private IP addresses.
  4. Network Load Balancer — Layer 4 (TCP/UDP); high-performance networking.
  5. Proxy Load Balancer — terminates client connections; supports SSL offloading.
C. Layer 7 vs Layer 4 — quick check
LayerScopeExamples
Layer 7 (Application)Global / Regional, HTTP(S), SSL terminationGlobal External HTTP(S), Regional External Application, Internal Application, Proxy
Layer 4 (Transport)TCP / UDP, high performanceNetwork Load Balancer
Memory hook: Layer 7 = HTTP(S) smart routing · Layer 4 = TCP/UDP raw throughput.
8 Cloud Security & Encryption
A. Introduction & objectives
  • Cloud security protects applications, data and infrastructure hosted in cloud environments.

Objectives — CIA Triad

  • Confidentiality
  • Integrity
  • Availability
B. Security layers
  • Physical security
  • Network security
  • Identity management
  • Application security
  • Data protection
Memory hook: Physical → Network → Identity → Application → Data.
C. Shared Responsibility Model
  • Security responsibilities are divided between the cloud provider and the customer.
Google secures… The cloud — physical infrastructure, data centres, hardware, core network and the managed-service foundations.
Customer secures… What is put in the cloud — data, identities, applications and configurations.
Memory hook: Google secures the cloud · you secure what's IN the cloud.
D. Encryption at rest & in transit
  • Encryption protects data from unauthorized access by converting it into unreadable ciphertext.

A. Encryption at Rest

  • Protects stored data.
  • Enabled by default.
  • Uses AES-256 encryption.
  • Managed by Google or the customer.

B. Encryption in Transit

  • Protects data while moving across networks.
  • TLS/SSL encryption.
  • IPSec VPN.
  • HTTPS communication.
E. Customer key options

C. Customer-Managed Encryption Keys (CMEK)

  • Keys stored in Cloud Key Management Service (Cloud KMS).
  • Customer controls key rotation and lifecycle.

D. Customer-Supplied Encryption Keys (CSEK)

  • Customer provides encryption keys for selected storage services.
  • Google does not store the keys.
OptionWho manages the keyWhere stored
Encryption at rest (default)GoogleGoogle-managed
CMEKCustomerCloud KMS
CSEKCustomerNot stored by Google
Memory hook: REST = AES-256 by default · TRANSIT = TLS/SSL · CMEK = KMS · CSEK = you supply, Google doesn't keep.
