1 General Strategy
A. What is divide and conquer?
  • A strategy of solving a large problem by:
    • Breaking the problem into smaller sub-problems
    • Solving the sub-problems
    • Combining them to get the desired output
  • Recursion is used to implement divide and conquer.
  • After dividing, the sub-problems are the same as the main problem (only smaller) — this is why recursion works.
B. The three steps
  1. Divide — divide the given problem into sub-problems using recursion.
  2. Conquer — solve the smaller sub-problems recursively. If a sub-problem is small enough, solve it directly (base case).
  3. Combine — combine the solutions of the sub-problems to solve the original problem.
Memory hook: Divide → Conquer → Combine. (For merge sort, conquer and combine happen side by side.)
C. General method & standard algorithms

The following algorithms are based on the divide-and-conquer approach:

  • Max–Min Problem
  • Merge Sort
  • Quick Sort
  • Binary Search
  • Strassen's Matrix Multiplication
  • Karatsuba Algorithm (fast integer multiplication)
  • Closest Pair of Points
  • Selection Problem (QuickSelect, Median of Medians)
D. Worked example — sorting an array
  1. Divide the array into two halves.
  2. Divide each sub-part recursively into two halves until you get individual elements.
  3. Combine the individual elements in a sorted manner — here the conquer and combine steps go side by side.
[ 38 27 43 3 9 82 10 ] / \ [38 27 43 3] [9 82 10] / \ / \ [38 27] [43 3] [9 82] [10] / \ / \ / \ | 38 27 43 3 9 82 10 \ / \ / \ / | [27 38] [3 43] [9 82] [10] \ / \ / [3 27 38 43] [9 10 82] \ / [3 9 10 27 38 43 82]
E. General recurrence form
T(n) = a·T(n/b) + f(n) a = number of sub-problems n/b = size of each sub-problem f(n) = cost of dividing + combining // examples from this unit Binary search : T(n) = 1·T(n/2) + O(1) Merge sort : T(n) = 2·T(n/2) + O(n) Quick sort (best): T(n) = 2·T(n/2) + O(n) Max–Min : T(n) = 2·T(n/2) + 2 Majority (DAC) : T(n) = 2·T(n/2) + O(n)
2 Binary Search
A. What is binary search?
  • An efficient algorithm used to find a specific element in a sorted array or list.
  • Operates by repeatedly dividing the search interval in half until the target is found or the interval is empty.
  • The element is always searched in the middle of a portion of the array.
⚠ Binary search always works on sorted elements.
B. How it works — iterative
  1. Initialization — start with two pointers, low and high. Initially low = 0 and high = n − 1.
  2. Iteration — while low ≤ high:
    • Calculate mid = (low + high) / 2 — optimised form: mid = low + (high − low)/2 to avoid overflow.
    • Compare arr[mid] with the target:
      • equal → search successful, return mid.
      • less than target → set low = mid + 1 (search right half).
      • greater than target → set high = mid − 1 (search left half).
  3. Termination — if low exceeds high, the target is not present; return −1 or indicate failure.
int binarySearch(int arr[], int n, int key) { int low = 0, high = n − 1; while (low <= high) { int mid = low + (high − low) / 2; // overflow-safe if (arr[mid] == key) return mid; else if (arr[mid] < key) low = mid + 1; else high = mid − 1; } return −1; }
C. Recursive version & recurrence
int binarySearchRec(int arr[], int low, int high, int key) { if (low > high) return −1; // base case: not found int mid = low + (high − low) / 2; if (arr[mid] == key) return mid; // base case: found if (arr[mid] < key) return binarySearchRec(arr, mid + 1, high, key); return binarySearchRec(arr, low, mid − 1, key); }

Analysis

T(n) = T(n/2) + 1 // 1 comparison + recurse on one half T(1) = 1 // base case // expand: T(n) = T(n/2) + 1 = T(n/4) + 2 = T(n/8) + 3 = … = T(n/2ᵏ) + k // stop when n/2ᵏ = 1 → k = log₂n T(n) = T(1) + log₂n = 1 + log₂n = O(log n)

Case analysis from the notes

  • Case 1: item = A[mid] → LOC = mid. This is the best case with T(n) = 1.
  • Case 2: item ≠ A[mid] → split the array into two equal parts of size n/2, find the midpoint of the chosen half and compare again. Repeat until found.
D. Time complexity — best, worst, average
CaseComplexityWhen it happens
BestO(1)Element found at the middle position in the very first check — only one comparison.
WorstO(log n)Element is at the beginning or end, or not present at all — the array keeps halving until the space is empty. Number of steps ≈ log₂(n).
AverageO(log n)Element may be anywhere; since half the elements are eliminated at each step, the average number of comparisons also grows as log₂(n).
Memory hook: Binary search = halve the space each time → O(log n).
3 Merge Sort
A. What is merge sort?
  • A Divide and Conquer algorithm that works in 3 steps:
    1. Divide — break the array into two halves.
    2. Conquer — sort each half recursively (solve each smaller piece).
    3. Merge — join the two sorted halves into one sorted array.
B. Algorithm & merge function
MERGE_SORT(arr, st, end) if st < end then mid = st + (end − st) / 2 MERGE_SORT(arr, st, mid) // sort left half MERGE_SORT(arr, mid + 1, end) // sort right half MERGE(arr, st, mid, end) // merge two halves end if
MERGE(arr, st, mid, end) create empty array temp i = st; j = mid + 1; k = st // comparison loop while i ≤ mid AND j ≤ end do if arr[i] ≤ arr[j] then temp[k] = arr[i]; i = i + 1 else temp[k] = arr[j]; j = j + 1 end if; k++ end while // leftover left-half loop while i ≤ mid do temp[k] = arr[i]; i = i + 1; k++ end while // leftover right-half loop while j ≤ end do temp[k] = arr[j]; j = j + 1; k++ end while // copy temp back into original array for k = st to end arr[k] = temp[k] end for END MERGE
C. Recurrence & complexity
T(n) = 2·T(n/2) + O(n) ↑ ↑ 2 halves merging cost // recursion tree: log n levels × O(n) work per level T(n) = O(n log n)

Why log n levels? Each level halves the array size, so after k levels the size is n/2ᵏ. The leaves are reached when n/2ᵏ = 1 → k = log₂n.

CaseComplexityReason
BestO(n log n)Even if the array is already sorted, merge sort still divides and merges.
WorstO(n log n)Even for a reverse-sorted array, the same number of comparisons and merges occur.
AverageO(n log n)The number of comparisons and merges does not change significantly across inputs.
SpaceO(n)Needs extra memory to hold temporary sub-arrays while merging.
Memory hook: Merge sort = O(n log n) in all cases, but pays O(n) extra space.
D. Merge example — two sorted halves
Left half : [3, 27, 38, 43] Right half : [9, 10, 82] i→3 j→9 compare 3 ≤ 9 → temp[3] i→27 j→9 compare 27 > 9 → temp[9] i→27 j→10 compare 27 > 10 → temp[10] i→27 j→82 compare 27 ≤ 82 → temp[27] i→38 j→82 compare 38 ≤ 82 → temp[38] i→43 j→82 compare 43 ≤ 82 → temp[43] i done → copy remaining 82 → temp[82] Result: [3, 9, 10, 27, 38, 43, 82]
4 Quick Sort
A. Core idea & partitioning
  • Pick a pivot element (last element, first element, or random).
  • Partition the array so that:
    • elements smaller than the pivot go to the left,
    • elements larger than the pivot go to the right.
  • The pivot is now in its final sorted position.
  • Recursively sort the left and right sub-arrays.
Before: [ 54 78 63 92 45 86 15 28 37 ] pivot = 37 (last) After : [ 15 28 37 92 45 86 54 78 63 ] ← notes' trace ↑ pivot in place at index 2 Correct partition (all left < 37, all right > 37): [ 15 28 37 45 54 63 78 86 92 ] ↑ pivot fixed, recurse both sides
B. Recurrence relations — all cases
// notation from the notes n = L + 1 + R // left + pivot + right n = k + 1 + r // k = size of left part, r = n − k − 1 = size of right r = n − k − 1 // WORST CASE — pivot is always the smallest or largest T(n) = T(n − 1) + n = T(n − 1) + Θ(n) = Θ(n²) // e.g. pivot = first element on sorted input // BEST CASE — pivot always splits the array in half T(n) = 2·T(n/2) + n = Θ(n log n) // AVERAGE CASE — pivot splits at some position k T(n) = T(k) + T(n − k − 1) + n // assume the split is on average balanced: T(k) ≈ T(n/2) T(n) = 2·T(n/2) + n = Θ(n log n)
C. Deriving the average case (completed)

If the pivot is equally likely to land in any of the n positions, average over all splits:

T(n) = (1/n) · Σk=0n−1 [ T(k) + T(n−1−k) ] + Θ(n) = (2/n) · Σk=0n−1 T(k) + Θ(n) // solving this recurrence gives: T(n) = Θ(n log n) // expected number of comparisons (Hoare): E[C(n)] = 2n·ln n ≈ 1.39 · n log₂n
✎ Completed The notes state T(n) = T(k) + T(n−k−1) + n and then say "we consider T(k) ≈ T(n/2)". The rigorous step is the averaging over all n equally likely pivot positions, which produces (2/n)·ΣT(k) + Θ(n) and solves to Θ(n log n).

5 Majority Element
A. The problem & four approaches

An element is the majority element if it appears more than n/2 times in an array of size n.

ApproachTimeSpaceQuality
Naïve / Brute forceO(n²)O(1)Good solution
SortingO(n log n)O(1) or O(n)Better solution
Divide & ConquerO(n log n)O(log n)Better solution
Boyer–Moore VotingO(n)O(1)Optimal solution
B. Approach 1 — Naïve / brute force
int findMajorityElement(int arr[], int n) { for (int i = 0; i < n; i++) { int count = 0; // count occurrences of arr[i] for (int j = 0; j < n; j++) { if (arr[j] == arr[i]) count++; } // check if it's the majority element if (count > n / 2) return arr[i]; } return −1; // no majority element }

O(n²) time · O(1) space

C. Approach 2 — Sorting
  • Key insight: if a majority element exists, it must occupy the middle index n/2 after sorting.
int findMajorityElement(int arr[], int n) { qsort(arr, n, sizeof(int), compare); // step 1: sort int candidate = arr[n / 2]; // step 2: middle element int count = 0; for (int i = 0; i < n; i++) { // step 3: count if (arr[i] == candidate) count++; } if (count > n / 2) return candidate; // step 4: verify return −1; }

O(n log n) time · space O(1) or O(n) depending on the sort

D. Approach 3 — Divide & Conquer

Algorithm

  • Divide: split the array into two halves.
  • Conquer: recursively find the majority element in both halves.
  • Combine:
    • If both halves return the same element → it is the majority.
    • Otherwise, count occurrences of both candidates in the entire range and return the one that appears more than N/2 times.
int findMajorityElementDC(int arr[], int left, int right) { // base case: single element if (left == right) return arr[left]; // divide int mid = left + (right − left) / 2; // conquer int leftMajor = findMajorityElementDC(arr, left, mid); int rightMajor = findMajorityElementDC(arr, mid + 1, right); // combine: same candidate → done if (leftMajor == rightMajor) return leftMajor; // otherwise count both in the full range int leftCount = countOccurrences(arr, left, right, leftMajor); int rightCount = countOccurrences(arr, left, right, rightMajor); int size = right − left + 1; if (leftCount > size / 2) return leftMajor; if (rightCount > size / 2) return rightMajor; return −1; // no majority element }

Recurrence

T(n) = 2·T(n/2) + O(n) ↑ ↑ 2 subproblems counting occurrences in the range T(n) = O(n log n)

O(n log n) time · O(log n) space (recursion stack)

E. D&C worked example — [3, 3, 4, 2, 4, 4, 2, 4, 4]

Step 1 — Divide the full array

arr = {3, 3, 4, 2, 4, 4, 2, 4, 4} Left half : {3, 3, 4, 2, 4} Right half : {4, 2, 4, 4}

Step 2 — Recursively divide the left half {3, 3, 4, 2, 4}

{3, 3, 4, 2, 4} ├── {3, 3, 4} │ ├── {3} → majority 3 │ ├── {3} → majority 3 │ └── {4} → majority 4 └── {2, 4} ├── {2} → majority 2 └── {4} → majority 4

Combining the left half

combine {3} and {3}: leftMajor = 3, rightMajor = 3 → same candidate → majority = 3 combine {3, 3} and {4}: leftMajor = 3, rightMajor = 4 count 3 → 2 times; count 4 → 1 time → majority = 3 combine {3, 3, 4} and {2, 4}: leftMajor = 3, rightMajor = 4 count 3 → 2 times; count 4 → 2 times neither > 5/2 → no majority in left half

Step 2 (cont.) — Right half {4, 2, 4, 4}

{4, 2, 4, 4} → 4 is the majority element in this half

Step 3 — Combine left and right

Left Major from {3, 3, 4, 2, 4} : 3 Right Major from {4, 2, 4, 4} : 4 Count occurrences in the entire array {3, 3, 4, 2, 4, 4, 2, 4, 4}: 3 occurs 2 times 4 occurs 5 times n/2 = 9/2 = 4.5 5 > 4.5 → 4 is the majority element ✓
✎ Note The notes say "the majority element in {3,3,4,2,4} is 3", but in the sub-array {3,3,4,2,4} of size 5, 3 appears twice and 4 appears twice — neither is a majority within that half. The algorithm still returns a candidate, and the final combine step correctly identifies 4 using the full-array count. The result is unchanged.
F. Approach 4 — Boyer–Moore Voting (optimal)
  • Moore's algorithm only gives a potential candidate — you must verify occurrences afterwards.
  • Two phases:
    1. Candidate phase — find a candidate in O(n).
    2. Verification phase — count the candidate's occurrences; confirm it is > n/2.
int findMajorityElement(int arr[], int n) { int candidate = −1, count = 0; // Phase 1: find a candidate for (int i = 0; i < n; i++) { if (count == 0) { candidate = arr[i]; count = 1; } else if (arr[i] == candidate) { count++; } else { count−−; } } // Phase 2: verify the candidate count = 0; for (int i = 0; i < n; i++) { if (arr[i] == candidate) count++; } if (count > n / 2) return candidate; return −1; }

O(n) time · O(1) space

6 Simultaneous Max & Min
A. D&C approach
  • Divide: split the array into two halves.
  • Conquer: recursively find the maximum and minimum in each half.
  • Combine: compare the results from both halves to get the final maximum and minimum.

Key advantage: the max of each group is compared with only the max of the other group, and min with only the min — that is what saves comparisons.

B. Algorithm
findMinMaxDAC(arr, low, high): // Base case 1: only one element if (low == high) { min = arr[low]; max = arr[low]; } // Base case 2: two elements → compare directly if (high == low + 1) { if (arr[low] < arr[high]) { min = arr[low]; max = arr[high]; } else { min = arr[high]; max = arr[low]; } } // Divide: find middle index mid = (low + high) / 2 // Conquer: recursively find min & max in left and right subarrays left = findMinMaxDAC(arr, low, mid) right = findMinMaxDAC(arr, mid + 1, high) // Combine: merge results if (left.min < right.min) min = left.min; else min = right.min; if (left.max > right.max) max = left.max; else max = right.max;
C. Recurrence & comparison count
T(n) = 2·T(n/2) + 2 ↑ ↑ 2 halves 2 comparisons to merge min and max // base cases T(1) = 0 // single element: min = max, no comparison T(2) = 1 // two elements: one comparison // solving: T(n) = 2·T(n/2) + 2 → T(n) = (3n/2) − 2 comparisons T(n) = O(n) // linear time
✎ Completed The notes state "uses 3n/2 − 2 comparisons" and give the answer 748 for an exercise. Solving 3n/2 − 2 = 748 gives 3n/2 = 750 → n = 500. So the exercise was: how many comparisons for n = 500 elements? Answer = 748. ✓
D. Linear approach vs D&C approach

Linear (naïve) approach — initialise max and min to the first element, then scan:

For input 1 2 3 4: max = 1 → compare with 2, 3, 4 min = 1 → compare with 2, 3, 4 For input 4 3 2 1: max = 4 min = 4 → compare with 3, 2, 1
ApproachComparisonsBestWorst
Linearn−1 (best) to 2(n−1) (worst)n−12(n−1)
Divide & ConquerAlways 3n/2 − 23n/2 − 23n/2 − 2

Why D&C is better: the linear approach can take up to 2(n−1) comparisons in the worst case. D&C guarantees 3n/2 − 2, which is always fewer for n > 2. It is a consistent improvement, not just an average one.

Memory hook: Max & Min D&C = 3n/2 − 2 comparisons, always O(n).
E. Worked example — [3, 1, 9, 4, 7, 2]
[3, 1, 9, 4, 7, 2] / \ [3, 1, 9] [4, 7, 2] / \ / \ [3] [1, 9] [4] [7, 2] | / \ | / \ min=max=3 1 9 min=max=4 7 2 min=1,max=9 min=2,max=7 \ / \ / [3,1,9]: min=1, max=9 [4,7,2]: min=2, max=7 \ / final: min = min(1,2) = 1 max = max(9,7) = 9

Comparison count: 3(6)/2 − 2 = 9 − 2 = 7 comparisons.

7 Selection Problem & QuickSelect
A. The problem & two ways to solve it
  • Find the k-th smallest (or k-th largest) element in an unsorted array using Divide and Conquer.
ApproachTimeNotes
Sorting + picking k-th elementO(n log n)Overkill — sorts the whole array
QuickSelectO(n) average, O(n²) worstOnly processes one side of the partition
Median of MediansO(n) worst caseGuarantees a good pivot
Key insight: we only need one element, not the entire sorted array — so we use QuickSelect.
B. How QuickSelect works
  1. Choose a pivot (e.g. last element).
  2. Partition — place elements smaller than the pivot on the left and larger on the right.
  3. Compare the pivot position with k−1 (0-based index of the k-th smallest):
    • If pivotIndex == k−1 → found, return the pivot.
    • If pivotIndex > k−1 → the answer is in the left sub-array.
    • If pivotIndex < k−1 → the answer is in the right sub-array.
  4. Recurse on the one relevant side only — this is why QuickSelect beats QuickSort.
C. Worked example 1 — [8, 3, 7, 1, 5], find 3rd smallest

Step 1: Choose pivot — take the last element. Pivot = 5.

Step 2: Partition — elements smaller than 5 go left, larger go right.

Before: [8, 3, 7, 1, 5] After : [3, 1, 5, 8, 7] ↑ ↑ ↑ ↑ ↑ index: 0 1 2 3 4 3, 1 < 5 8, 7 > 5 Pivot 5 is now at index 2.

Step 3: Compare pivot position

We want: k = 3rd smallest In 0-based programming: k − 1 = 2 Pivot index = 2 Since pivotIndex == k − 1 → we found the answer 3rd smallest = 5 ✓

Array: [10, 4, 5, 8, 6, 11, 26] — find the 5th smallest.

Partition with pivot = 6:

Memory hook: QuickSelect recurses into one side only → O(n) average instead of O(n log n).

8 Median of Medians
A. Why we need it
  • The Median of Medians algorithm finds the k-th smallest element (Selection Problem) in O(n) worst-case time.
  • Why not QuickSelect?
    • QuickSelect is usually fast, but if it picks a bad pivot repeatedly, it becomes O(n²).
    • Median of Medians guarantees a good pivot, so the worst case becomes O(n).
B. Algorithm steps
  1. Divide into groups — split the n elements into groups of 5 (the last group may be smaller).
  2. Sort each group — sorting 5 elements takes constant time.
  3. Find each group's median — the 3rd element of each sorted group.
  4. Find the median of these medians — recursively call the same algorithm on the list of n/5 medians. This is the pivot.
  5. Partition the original array around this pivot.
  6. Recurse into one side, exactly like QuickSelect.
n elements ↓ split into groups of 5 [n/5 groups] ↓ sort each group (O(1) each) [n/5 medians] ↓ recursively find the median of these medians PIVOT → guaranteed good split ↓ partition + recurse on one side
C. Recurrence & complexity
T(n) = T(n/5) // recurse on the n/5 medians + T(7n/10) // recurse on the larger partition side + O(n) // grouping, sorting groups of 5, partitioning // why 7n/10? The pivot has at least 3n/10 elements below it // and at least 3n/10 elements above it, so at most 7n/10 // remain on the larger side. // Since n/5 + 7n/10 = 9n/10 < n, the work forms a // decreasing geometric series: T(n) = O(n)
D. Why sorting doesn't make it O(n log n)
✎ Key exam point Q: Why doesn't Median of Medians take O(n log n) even though sorting is used?

A: Because it sorts only groups of 5 elements. Sorting a group of 5 takes constant time O(1). There are n/5 groups, so the total sorting cost is (n/5) × O(1) = O(n).

There is no global sort — only many tiny local sorts. That is why the overall complexity stays linear.
