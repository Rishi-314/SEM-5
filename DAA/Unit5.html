1 Backtracking Strategy
A. What is backtracking?
  • Like trying different paths — when you hit a dead end, you backtrack to the previous choice and try a different route.
  • A problem-solving technique that finds a solution incrementally by trying different options and undoing them if they lead to a dead end.
  • A systematic trial-and-error technique: build a solution step by step and undo ("backtrack") whenever you hit a dead end.
B. Core idea — 5 steps
  1. Make a choice.
  2. Check whether the choice is valid.
  3. If valid → continue.
  4. If invalid → go back (backtrack).
  5. Try another choice.
Memory hook: Choose → Check → Continue / Backtrack → Try another.
C. Real-life analogy — the junction

You reach a junction:

A → B → DEAD END ✗ don't continue walking through the wall ↩ BACKTRACK A → C → D → EXIT ✓
  • Backtracking means going back to the most recent decision point and trying another option.
D. Where it is used
  • Situations where you need to explore multiple possibilities to solve a problem.
  • Examples: searching for a path in a maze, solving puzzles like Sudoku.
  • When a dead end is reached, the algorithm backtracks to the previous decision point and explores a different path until a solution is found or all possibilities are exhausted.
E. When NOT to use backtracking
  • Greedy or DP fits better — if the problem can be solved directly using a greedy strategy or dynamic programming, backtracking is overkill.
  • No pruning possible — if all branches must be explored anyway (no constraints to cut early), brute force or iterative methods may be simpler.
  • Large input size — backtracking can be exponential in time; for very large inputs without strong pruning it becomes impractical.
  • Single optimal solution — if the task only needs one best solution with clear optimisation criteria, DP, greedy or graph search may be faster.
Memory hook: Backtracking shines when constraints let you prune early.
2 General Approach & Working
A. Working steps
  1. Choose a possible solution component.
  2. Verify if it satisfies the constraints.
    • If it satisfies → proceed to the next step.
    • If it violates → backtrack and try another option.
  3. Repeat until a complete solution is found.
B. Algorithm structure (pseudocode)
Backtrack(solution): if solution is complete: process the solution return for each possible choice: if choice is valid: make the choice Backtrack(solution) // recursive call undo the choice // backtrack
C. Detailed explanation
Base case If the solution is complete, process it and return.
Recursive case Loop through all possible choices at the current step; check validity; if valid, include the choice and move to the next step.
  • If no valid solution is found, backtrack by undoing the last choice.
  • The undo step is what makes backtracking different from plain recursion — the state is restored before trying the next branch.
D. Complexity
  • Time complexity depends on the problem.
  • In general, worst-case complexity is exponential — the algorithm may need to explore a large portion of the state-space tree.
  • Pruning (constraint checks) is what keeps the tree manageable in practice.
Memory hook: Backtracking = DFS on the state-space tree + pruning.
3 Types of Backtracking Problems
A. The three categories
  1. Decision Problems — determine whether a solution exists (yes/no).
    Example: checking if a Hamiltonian cycle exists in a graph.
  2. Optimization Problems — find the best solution from multiple possibilities.
    Example: Traveling Salesman Problem (TSP) — shortest route covering all cities.
  3. Constraint Satisfaction Problems (CSPs) — a solution must satisfy a given set of constraints.
    Example: Sudoku, N-Queens, Graph Coloring.
Memory hook: Decision = "does it exist?" · Optimization = "which is best?" · CSP = "satisfy all rules".
B. Which type uses backtracking most?
  • Generally, constraint satisfaction problems can be solved using backtracking.
  • Backtracking is the natural fit because constraints let us prune partial solutions as soon as they violate a rule.
TypeAnswer soughtExample

OptimizationBest solutionTSP shortest route
CSPAny solution satisfying constraintsSudoku, N-Queens, Graph Coloring
4 Explicit & Implicit Constraints
A. What is a constraint?
  • A condition that a solution must satisfy.
  • Backtracking problems involve two types of constraints: Explicit and Implicit.
B. Explicit constraints — WHAT values are allowed
  • Define the properties of a valid solution.
  • Directly define the possible values / options for a component of the solution.
  • Tell us WHAT values are allowed.
  • If an explicit constraint is violated, backtracking occurs immediately.

Examples

  • N-Queens — no two queens should be in the same row, column or diagonal.
  • Graph Coloring — adjacent nodes must not have the same colour.
  • Student rule — only third-year students can participate (allowed: third-year; not allowed: first, second, final year).
C. Implicit constraints — can the choices go together?
  • Define the rules for selecting the next possible solution step.
  • They dynamically evolve as the solution is built.
  • Tell us whether the choices we have made can go together.

Examples

  • Sudoku — a number can be placed in a cell only if it is not present in the same row, column or box.
  • Word Search — the next selected letter must form a valid word.
D. Worked example — selecting 2 students from A, B, C, D, E
Explicit constraint Rule: only students A, B, C, D, E can be selected.
→ These are the allowed choices.
Tells us WHAT we can choose.
Implicit constraint Rule: A and B cannot be in the same team.
→ A alone allowed · B alone allowed · A + B not allowed.
Checks whether our selected choices can be together.
  • First choice: A → allowed.
  • Second choice: B → B is allowed to be selected, but A + B together are not allowed.
  • So B is rejected at this point and the algorithm backtracks to try another student.
Memory hook: Explicit = WHAT can I pick · Implicit = CAN my picks coexist.

5 N-Queens Problem
A. Problem statement
  • Place N queens on an N×N chessboard.
  • Constraint: no two queens attack each other — no two may share the same row, same column, or same diagonal.
  • This is a classic Constraint Satisfaction Problem solved by backtracking.
4-Queens — one valid solution . Q . . . . . Q Q . . . . . Q .
B. Constraints applied to N-Queens
  • Explicit constraint: no two queens in the same row, column or diagonal.
  • Implicit constraint: when placing queen i in column i, it must not conflict with any queen already placed in columns 1…i−1.
  • Column conflict is avoided by construction — place exactly one queen per column.
  • Row and diagonal conflicts are checked at each placement.
// conflict check for a new queen at (row r, column c) for each previously placed queen at (r', c'): if r == r' // same row or |r − r'| == |c − c'| // same diagonal return conflict return safe
C. Backtracking algorithm
Solve(col): if col > N: // base case: all queens placed print board return true for row = 1 to N: if isSafe(row, col): place queen at (row, col) // make choice if Solve(col + 1): // recurse return true remove queen from (row, col) // backtrack return false // no row works in this column
D. State-space tree (concept)
  • Each level of the tree corresponds to a column.
  • Each branch corresponds to a choice of row for that column.
  • A node is promising if no conflict exists with the queens placed so far.
  • Pruning happens when a queen placement violates row or diagonal constraints.
Level 1 (col 1): rows 1 2 3 4 Level 2 (col 2): only safe rows survive Level 3 (col 3): further pruning Level 4 (col 4): a complete path = a solution
E. Worked trace — 4-Queens

1Q1 in col 1 → row 1Place (1,1)
2Q2 in col 2 → try row 1, row 2Conflicts → try row 3 → place (3,2)
3Q3 in col 3 → try rows 1–4All conflict → backtrack

F. Solutions for N = 4

The 4-Queens problem has exactly 2 solutions (represented as the row of the queen in each column):

  • (2, 4, 1, 3)
  • (3, 1, 4, 2)
(2,4,1,3) (3,1,4,2) . Q . . . . Q . . . . Q Q . . . Q . . . . . . Q . . Q . . Q . .
Memory hook: N-Queens = place one queen per column, prune rows & diagonals.
6 Graph Coloring — Basics
A. Definition
  • Colouring the vertices of a graph so that no two adjacent vertices have the same colour.
  • Also called the vertex colouring problem.
  • If colouring uses at most m colours, it is called m-colouring.
B. Two versions of the problem
Decision problem "With given M colours and graph G, is such a colour scheme possible or not?"
→ answer is yes / no.
Optimization problem "Given M colours and graph G, find the minimum number of colours required for graph colouring."
→ answer is a number + scheme.

Graph colouring is both a decision problem and an optimization problem.

C. Chromatic number
  • The minimum number of colours needed to colour a graph is called its chromatic number, written χ(G).
  • For example, some graphs can be coloured with a minimum of 2 colours.
GraphChromatic number χ(G)
Empty graph (no edges)1
Even cycle (C₄, C₆, …)2
Odd cycle (C₃, C₅, …)3
Tree / bipartite graph2
Complete graph Kₙn
Memory hook: Chromatic number = smallest palette that works.
D. Why backtracking fits graph colouring
  • Assigning colours vertex by vertex builds a partial colouring.
  • As soon as an adjacent pair shares a colour, the partial colouring is invalid → prune and backtrack.
  • The explicit constraint (adjacent vertices differ) is checked at every step, giving early pruning.
7 Graph Coloring — Applications
A. Map colouring
  • Ensures no two adjacent regions (countries, states, districts) share the same colour.
  • Used in geographical maps to differentiate neighbouring areas.
B. Task scheduling
  • Assigns resources (CPU, workers, classrooms) to tasks while avoiding conflicts.
  • Example: parallel processing where dependent tasks get different colours to avoid execution conflicts.
C. Timetable scheduling
  • Allocates different time slots for classes / exams.
  • Ensures no two overlapping events occur at the same time.
D. Assignment problems
  • Assigns workers to tasks, ensuring no worker is assigned two conflicting tasks.
  • Example: assigning interviewers to candidates in a recruitment process.
E. Conflict resolution
  • Used in networks, databases and traffic systems to prevent conflicts.
  • Example: deadlock prevention in operating systems by ensuring non-conflicting resource allocation.
F. Sudoku puzzle solving
  • Each cell in a Sudoku grid represents a node in a graph.
  • Each number represents a different colour.
  • Adjacent cells (same row, column or box) must not share a number — exactly the graph colouring constraint.
Memory hook: Maps · Tasks · Timetables · Assignments · Conflicts · Sudoku.
8 Graph Coloring — Algorithm & Example
A. Backtracking algorithm for m-colouring
Color(vertex v): if v > N: // all vertices coloured print colour assignment return true for c = 1 to m: // try each of the m colours if isSafe(v, c): // no adjacent vertex has colour c colour[v] = c // make choice if Color(v + 1): // recurse to next vertex return true colour[v] = 0 // backtrack return false // no colour works for v

The explicit constraint is applied inside isSafe: for every neighbour u of v, colour[u] ≠ c.

B. Worked example — graph used

Vertices A, B, C, D. Edges: A–B, B–C, C–D, D–A, A–C.

A ----- B | \ | | \ | | \ | D ----- C Adjacency: A→B,C,D · B→A,C · C→A,B,D · D→A,C

This graph contains a triangle A–B–C, so it needs at least 3 colours.

C. Trace with m = 2 → no solution (backtracking exhausts)
StepActionResult
1A ← colour 1OK
2B ← try 1Conflict with A → try 2 → B = 2
3C ← try 1Conflict with A → try 2
4C ← try 2Conflict with B → no colour left → backtrack
5B ← exhaustedbacktrack
6A ← try 2OK
7B ← try 1OK → B = 1
8C ← try 1Conflict with B → try 2
9C ← try 2Conflict with A → no colour left → backtrack
10B ← try 2Conflict with A → exhausted → backtrack
11A ← exhaustedNo 2-colouring exists → return false

Conclusion: the search tree is fully exhausted with m = 2, proving the graph is not bipartite and χ(G) ≥ 3.

D. Trace with m = 3 → solution found
StepVertexColour triedOutcome
1A1OK → A = 1
2B1 → conflict A · 2 → OKB = 2
3C1 → conflict A · 2 → conflict B · 3 → OKC = 3
4D1 → conflict A, C · 2 → OK (D not adjacent to B)D = 2 → solution ✓
A = 1 B = 2 D = 2 C = 3 Check: A–B (1,2) ✓ B–C (2,3) ✓ C–D (3,2) ✓ D–A (2,1) ✓ A–C (1,3) ✓
E. Chromatic number of the example graph
  • m = 2 fails → χ(G) ≥ 3.
  • m = 3 succeeds → χ(G) ≤ 3.
  • Therefore χ(G) = 3.

This is exactly how the optimization version is solved by backtracking: try m = 1, 2, 3, … until a colouring is found; the first m that works is the chromatic number.

Memory hook: Decision asks "can m colours work?" · Optimization asks "what is the smallest m?" — same backtracking search, different stopping rule.
