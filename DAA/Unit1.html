1 Algorithm Fundamentals
A. Definition of an algorithm
  • Any well-defined computational procedure that takes some value(s) as input and produces some value(s) as output.
  • A sequence of computational steps that transform the input into the output.
Memory hook: Algorithm = input → sequence of well-defined steps → output.
B. Five ways of writing an algorithm
  1. Natural Language (Plain English) — simple, human-readable steps; good for explaining logic informally.
    Example Find the maximum of three numbers — written as plain steps.
  2. Pseudocode — structured like programming code but language-independent; preferred in DAA for clarity and analysis.
  3. Flowchart — visual representation using ovals, diamonds and rectangles; useful for understanding flow and logic; best for beginners or simple processes.
  4. Programming Language — actual implementation in C, Python, Java, etc.; useful for running and testing.
  5. Mathematical / Recursive Notation — used for recursive algorithms and mathematical problems (e.g. Factorial).
Memory hook: Natural · Pseudocode · Flowchart · Code · Math/Recursive.
C. Course context

Prerequisites: basic programming skills, data structures, discrete structures.

Course objectives

  1. Understand asymptotic notations; apply mathematical techniques to find time and space complexity.
  2. Build foundations for solving computational problems using different design strategies.
  3. Select the appropriate algorithm design strategy for real-world problems.
  4. Understand NP-hardness and NP-completeness and their relationship with intractability of decision problems.
  5. Understand randomized and approximation algorithms for given computational problems.
2 Analysis of Algorithms
A. What is analysis of algorithms?
  • The process of evaluating an algorithm's efficiency in terms of:
    • Time — how fast it runs.
    • Space — how much memory it uses.
  • Helps decide which algorithm is best suited for a given problem, especially when there are multiple alternatives.
  • Ensures the program works well with large amounts of data or complex problems.
B. Real-time example — the road trip

You are planning a road trip with two routes:

Route A — highway, minimal traffic, but longer Slower but uses less memory.
Example: recursive Fibonacci with no array — slower because it recalculates values, but uses little memory.
Route B — shorter, but heavy traffic Faster but uses more memory (frequent braking, acceleration, idling, more fuel).
Example: Fibonacci with memoization or a DP table — faster due to reuse of computed values, but uses extra memory to store results.
Memory hook: Recursion = slow + low memory · DP = fast + more memory.
C. Why do we need complexity analysis?
  • Determines the amount of time and space resources required to execute an algorithm.
  • Used to compare different algorithms on different input sizes.
  • Helps determine the difficulty of a problem.
  • Measured by how much time and space (memory) it takes to solve a particular problem.
Memory hook: Complexity analysis = time + space + comparison + problem difficulty.
3 Orders of Growth
A. What "order of growth" means
  • The efficiency of an algorithm — how the time (or memory) taken increases when the input size n becomes bigger.
  • When input gets larger, does your algorithm take a little more time, a lot more time, or a crazy long time?
Growth rate = "How fast" the time increases as input grows.
B. Standard growth classes
OrderClassExampleWhy
O(1)ConstantIndexing a list itemTime does not depend on input size
O(log n)LogarithmicRepeatedly halving a numberGrows with logarithm of input size
O(n)LinearSumming a listProportional to input size
O(n²)QuadraticSumming each pair of numbersGrows quadratically with input size
O(n³)CubicMatrix multiplicationTriple nested loops
O(2ⁿ)ExponentialVisiting each node in a binary treeTime doubles with each additional input
C. Growth rate sequence — slowest to fastest
1 < log n < √n < n < n log n < n² < n³ < 2ⁿ < nⁿ Constant → Logarithmic → Square Root → Linear → Linearithmic → Polynomial → Exponential → Super-Exponential
  • Constant (1) — operations independent of n; always the slowest growth (e.g. f(n)=2, f(n)=6000).
  • Logarithmic (log n) — grows very slowly even for large n (e.g. log₁₀ 10 = 1, log₁₀ 100 = 2; binary search).
  • Square root (√n) — faster than logarithmic, slower than linear (for n = 100, √n = 10).
  • Linear (n) — grows directly proportionally to n (n = 100 → ~100 steps).
  • Linearithmic (n log n) — combines linear and logarithmic; common in efficient sorting like merge sort.
  • Polynomial (n², n³) — n² grows faster than n log n; n³ grows faster than n² (bubble sort, triple loops).
  • Exponential (2ⁿ) — grows much faster than any polynomial; for n = 10, 2ⁿ = 1024 (e.g. TSP, all subsets).
  • Super-exponential (nⁿ) — the fastest growth; for n = 5, nⁿ = 3125.
D. Real-life examples for each growth class
GrowthReal-life example
O(1)Picking the first book from a shelf — always one action, no matter how many books.
O(log n)Guessing a number 1–100 by asking "greater than 50?", then 75, then 88 — each guess halves the possibilities.
O(√n)Looking for a friend in a 10×10 crowd — checking one row and one column takes about √100 = 10 checks.
O(n)Counting students in a classroom one by one.
O(n log n)Organizing answer sheets by roll number with an efficient sort.
O(n²)Every student introducing themselves to every other student.
O(n³)Forming and checking every possible group of 3 students.
O(2ⁿ)Deciding ON/OFF for n lights — every new light doubles the combinations.
O(nⁿ)Each of n students independently picking any of n project topics.
Memory hook: 1 · log · √ · n · n log n · n² · n³ · 2ⁿ · nⁿ.
E. Simplifying examples
f(n) = 2n + 3 → O(n) // drop constants & lower-order terms f(n) = 500n + 700 → O(n) f(n) = n/200 + 6 → O(n) f(n) = 2 → O(1) f(n) = 3n² + 5n + 2 → O(n²) // n² dominates

Big-O ignores constants and lower-order terms to focus on the dominant factor that affects growth.

4 Asymptotic Notations
A. What asymptotic notation is
  • A way to describe the efficiency of an algorithm (time or space) with respect to input size.
  • Mathematical tools used to describe how fast an algorithm works when n → ∞.
  • Used to evaluate the performance of an algorithm in its best and worst case scenarios.
  • A method of defining the mathematical boundaries of run-time performance.

Algorithm A is asymptotically faster than B means:

  • For small inputs, B might be faster.
  • But for large inputs, A will eventually be better or more efficient.
B. f(n) and g(n)
f(n) The actual number of steps (or time or memory) your algorithm takes when the input size is n.
Example: f(n) = 3n² + 5n + 2.
g(n) A reference function used to compare with the actual work — a known growth pattern like 1, log n, n, n², 2ⁿ.
Example: g(n) = n².

Instead of saying "my algorithm takes 3n² + 5n + 7 steps", we say "it grows like n² → that is g(n)".

Memory hook: f(n) = what your algorithm does · g(n) = the reference growth pattern.
C. Big-O — upper bound (worst case)
  • Describes the upper bound or worst-case scenario.
  • "The algorithm will not take more time than this, even in the worst case."
  • Like ≤.
Mathematically: 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀

Example: if an algorithm runs in at most 5n + 3 steps, we say it is O(n).

3n + 5 ≤ 4n for all n ≥ 5 → f(n) = O(n) 3n + 5 ≤ 4n² for all n ≥ 5 → f(n) = O(n²) also true

Grocery checkout analogy: with n people in line and 1 minute per person, you wait up to n minutes → waiting time = O(n).

Big-O answers: "How bad can it get?"
D. Big-Ω — lower bound (best case)
  • Gives a lower bound on the time or space.
  • "At least this much time will be needed."
  • Shows the best case.
  • Like ≥.
Mathematically: 0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀

Laundry analogy: each shirt takes at least 1 minute; with n shirts, at least n minutes → time = Ω(n). Even if you multitask, you cannot do it in less than n minutes.

Unsorted list search:

  • Best case — item at first position → Ω(1)
  • Worst case — item at end → O(n)
  • So overall: Ω(1) and O(n)
Big-Ω answers: "What is the minimum time needed?"
E. Big-Θ — tight bound (exact)
  • Gives a tight bound on the time or space.
  • The algorithm takes at least and at most that much time — it grows exactly at that rate.
  • Like ==.
Mathematically: 0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀

Example: a for-loop that runs exactly n times in all cases → Time complexity = Θ(n).

Big-Θ answers: "Exactly how does it grow?"
F. Little-o and little-ω — strict bounds

Little-o (o) — strict upper bound

  • An upper bound that cannot be tight — a loose upper bound.
  • f(n) grows strictly slower than g(n) as n → ∞.
  • f(n) will never catch up to g(n), no matter how big n gets.

Slow walker vs fast runner: as the race gets longer, the walker's time grows much more slowly — it never catches up with the runner.

Little-ω (ω) — strict lower bound

  • f(n) grows strictly faster than g(n) as n → ∞.
  • g(n) is a loose lower bound of f(n) — but not tight.

Car vs cycle: as time goes on, the car always becomes faster than the cycle and keeps increasing the gap → car speed = ω(cycle speed).

Memory hook: o = strictly smaller · ω = strictly bigger · O/Ω allow equality, o/ω do not.

5 Case Analysis — Best / Average / Worst
A. Worst case
  • Shows the maximum time an algorithm might take.
  • Assumes the most difficult input for the algorithm.
  • Gives the upper bound (maximum limit) of time.
  • Linear search worst case = target at the last location → O(n).

Where used — critical systems:

  • Banking transactions — must process without delay even under heavy traffic.
  • Emergency services — must work quickly even with high call volume.
  • Flight control systems — must always respond quickly, even in turbulence or overload.
B. Best case
  • Shows the minimum time an algorithm can take.
  • Happens when the input is most favorable.
  • Gives the lower bound (smallest limit) of time.
  • Linear search best case = target at the first location → Ω(1).

Where it helps:

  • Sorting small lists — an already-sorted 5-name list shows the fastest performance.
  • Search engine cache — popular queries already cached return results almost instantly.
  • Autofill suggestions — exact matches with stored data make autofill as fast as possible.
C. Average case
  • Gives the expected time an algorithm takes for typical (random) input.
  • Lies between the best and worst case.
  • Assumes all inputs are equally likely.

Why average case is hard to use

  • We don't know the inputs — like a shop owner who can't predict how busy each day will be (festivals vs rainy days).
  • Complicated math — must consider every possible input and its probability.

Where average case applies:

  • Web search engines — most queries are typical; data is organized for fast retrieval.
  • Social media feeds — user activity follows general patterns (likes, comments).
D. Why we need all three
  • Decision making — developers choose the best algorithm based on time, memory and input size.
  • Scalability — helps know if the algorithm still works well for large inputs (worst-case matters most here).
  • Reliability — worst-case shows behaviour in the toughest situations.
  • Optimization — knowing how fast or slow an algorithm is lets developers find and eliminate inefficiencies.
E. Worked example — linear search on unsorted array
CaseWhere is the target?Time
BestFirst elementO(1)
AverageSomewhere in the middleO(n/2) → O(n)
WorstLast element or not presentO(n)
Memory hook: Best = first · Worst = last or absent · Average = middle → O(n).
6 Time & Space Complexity
A. Definitions
Time complexity How long the algorithm takes to run, based on the length of the input.
Space complexity How much memory the algorithm uses.

How time complexity is computed: consider the cost of each fundamental instruction and the number of times it is executed.

B. Standard loop patterns

Loop running n times → O(n)

for (i = 0; i < n; i++) print(i); // runs n times → f(n) = n → O(n)

Loop doubling each time → O(log n)

for (i = 1; i < n; i = i * 2); // i = 1, 2, 4, 8, 16, … ; after k iterations i = 2ᵏ // stops when 2ᵏ ≥ n → k = log₂ n → O(log n)

Nested loops → O(n²)

for (i = 0; i < n; i++) for (j = 0; j < n; j++) print(i, j); // runs n × n = n² times → f(n) = n²

Sum of consecutive integers → O(√n)

p = 0 for (i = 1; p < n; i++) p = p + i; // after k iterations: p = 1 + 2 + … + k = k(k+1)/2 // stops when k(k+1)/2 > n → k ≈ √(2n) → O(√n)
C. Conditional statements
  • The condition decides how many times the loop body executes.
  • If a condition is true → it executes one statement, which takes O(1).
  • If a condition is false → the enclosing loop may still run O(n) times.
Memory hook: sequential loops add → O(n) · nested loops multiply → O(n²).
D. Space complexity examples
AlgorithmSpaceWhy
Matrix multiplicationO(n²)Result matrix needs n² cells
Bubble sortO(1)Only a temp variable for swapping
Factorial (recursive)O(n)Call stack depth is n
Factorial (iterative)O(1)Only a running product variable
Memory hook: Recursive factorial = O(n) stack · Iterative = O(1).
7 Insertion Sort
A. How it works
  • Simple sorting algorithm that works like sorting playing cards in your hands.
  • Key operations: comparisons (find the correct position) and shifts (make room for the current element).
  • The array is virtually split into a sorted part and an unsorted part. Values from the unsorted part are picked and placed into the correct position in the sorted part.
B. Algorithm & steps
InsertionSort(arr): for i = 1 to length(arr) − 1: key = arr[i] j = i − 1 while j ≥ 0 and arr[j] > key: arr[j + 1] = arr[j] // shift element right j = j − 1 arr[j + 1] = key // insert key into correct position
  1. Start with the second element (the first is already "sorted").
  2. Take the current element as the key.
  3. Compare the key with its predecessor; if smaller, shift the larger element right.
  4. Continue comparing and shifting until the correct position is found.
  5. Place the key in its correct position.
  6. Repeat for all elements.
C. Worked trace — [5, 4, 10, 1, 6, 2]
StepiKeyActionArray after
1144 < 5 → shift 5; j = −1; insert at 04, 5, 10, 1, 6, 2
221010 > 5 → no shift; insert at j+1=24, 5, 10, 1, 6, 2
3311 < 10, 5, 4 → shift all three; insert at 01, 4, 5, 10, 6, 2
4466 < 10 → shift 10; 6 > 5 → stop; insert at 31, 4, 5, 6, 10, 2
5522 < 10, 6, 5, 4 → shift four; 2 > 1 → stop; insert at 11, 2, 4, 5, 6, 10

Output: 1, 2, 4, 5, 6, 10

Memory hook: Insertion sort best O(n) (sorted) · worst O(n²) (reverse) · space O(1).
8 Bubble Sort
A. How it works
  • Simple comparison-based sorting algorithm.
  • Repeatedly steps through the list, compares adjacent elements, and swaps them if they are in the wrong order.
  • This process continues until the list is sorted.
  • A swapped flag enables early termination when no swaps occur in a pass.
B. Algorithm
BUBBLE_SORT(array, n) for i = 0 to n − 2 do // outer loop = passes swapped = FALSE for j = 0 to n − i − 2 do // inner loop = comparisons if array[j] > array[j + 1] then swap(array[j], array[j + 1]) swapped = TRUE if swapped = FALSE then break // array is sorted → early exit
C. Dry run — [4, 3, 2, 1]
PassComparisons & swapsResult
14↔3, 4↔2, 4↔13, 2, 1, 4
23↔2, 3↔12, 1, 3, 4
32↔11, 2, 3, 4
4No swaps → break1, 2, 3, 4
D. Time complexity — all cases
CaseInputComparisonsComplexity
BestAlready sorted (1,2,3,4,5)n−1 in one pass, no swaps → early exitO(n)
AverageRandom order≈ n(n−1)/2O(n²)
WorstReverse order (5,4,3,2,1)n(n−1)/2 (maximum swaps)O(n²)

Space complexity: O(1).

Memory hook: Bubble sort best O(n) with early exit · worst O(n²) · space O(1).
9 Recurrence Relations
A. What is a recurrence relation?
  • A mathematical equation that defines a sequence or function using its own previous values.
  • Shows how the solution to a big problem depends on the solutions to smaller versions of the same problem.
  • Used to analyze the time complexity of recursive algorithms.
Memory hook: Recurrence = how T(n) depends on T(smaller).
B. Three methods to solve
  1. Substitution method — guess the solution and prove it by mathematical induction.
  2. Recursion tree method — represent the recurrence as a tree to analyze the work at each level.
  3. Master theorem — a shortcut for recurrences of the standard form T(n) = aT(n/b) + f(n).
Memory hook: Substitution (guess+prove) · Tree (visualize levels) · Master (formula).
C. Simple recurrence examples
// Example 1 — countdown T(n) = 1 if n = 0 = T(n − 1) if n > 0 → T(n) = O(n) // Example 2 — linear work per level T(n) = 1 if n = 0 = T(n − 1) + n if n > 0 → T(n) = O(n²) // Example 3 — Fibonacci T(n) = 0 if n < 0 = 1 if n = 1 = T(n − 1) + T(n − 2) if n > 1 → exponential ~ Θ(φⁿ)
D. Back substitution / iterative method
  • Also called recursion tree expansion or iterative method.
  • Repeatedly substitute the recurrence into itself until the base case is reached.

Example: T(n) = T(n−1) + 1

T(n) = T(n−1) + 1 = T(n−2) + 1 + 1 = T(n−3) + 1 + 1 + 1 … = T(n−k) + k // stop when n−k = 0 → k = n T(n) = T(0) + n = n + 1 = O(n)

Example: T(n) = T(n−1) + n

T(n) = T(n−1) + n = T(n−2) + (n−1) + n … = T(0) + 1 + 2 + … + n = n(n+1)/2 = O(n²)
E. Dividing functions & GP
  • If an algorithm takes input n, it can:
    • decrease it as n − 1
    • divide it as n/2
    • take a root function as √n

Geometric Progression (GP)

  • A sequence where each term after the first is found by multiplying the previous term by a fixed, non-zero number r (the common ratio).
  • Useful when solving divide-and-conquer recurrences with the recursion tree method.
Memory hook: Decrease → n−1 · Divide → n/2 · Root → √n.
10 Master Theorem
A. For decreasing functions
  • Can only be applied to decreasing and dividing recurring functions. If the relation is neither, the master theorem must not be applied.

General form

T(n) = a·T(n − b) + f(n) where a > 0, b > 0, f(n) = O(nᵏ), k ≥ 0, f(n) asymptotically positive
  • n — size of the problem
  • a — number of sub-problems in the recursion
  • n − b — size of the sub-problems (assumed equal)
  • f(n) — cost of work done outside the recursion = Θ(nᵏ)

Three cases

if a = 1 → T(n) = O(n^(k+1)) = O(n · f(n)) if a > 1 → T(n) = O(a^(n/b) · nᵏ) = O(a^(n/b) · f(n)) if a < 1 → T(n) = O(nᵏ) = O(f(n))
B. For dividing functions

General form

T(n) = a·T(n/b) + f(n) where a ≥ 1, b > 1, f(n) = Θ(nᵏ logᵖ n)

Two values to compute

  1. log_b a
  2. k

Three cases — compare log_b a with k

CaseConditionResult
Case 1log_b a > kΘ(n^(log_b a))
Case 2log_b a = kΘ(n^k · log^(p+1) n)
Case 3log_b a < kΘ(n^k · log^p n)
C. Worked example

Example: T(n) = 8T(n/2) + n²

a = 8, b = 2, f(n) = n² → k = 2 log_b a = log₂ 8 = 3 Compare: log₂ 8 = 3 > k = 2 → Case 1 T(n) = Θ(n^(log_b a)) = Θ(n³)
Memory hook: Compute log_b a and k · bigger → n^(log_b a) · equal → add log · smaller → n^k.
D. Master theorem quick-check list
  • Is the recurrence in the form a·T(n−b) + f(n) or a·T(n/b) + f(n)? If not → master theorem does not apply.
  • For decreasing: compare a with 1.
  • For dividing: compare log_b a with k.
  • If a < 1 in the decreasing form, the recursion shrinks — result is just O(f(n)).
11 Proof of Correctness
A. Why prove correctness?
  • Complexity analysis tells you how fast an algorithm runs; correctness proof tells you whether it produces the right answer.
  • An algorithm that is fast but wrong is useless.
B. Loop invariants — three steps
  1. Initialization — the invariant is true before the first iteration.
  2. Maintenance — if the invariant is true before an iteration, it remains true before the next one.
  3. Termination — when the loop terminates, the invariant gives a useful property that proves correctness.
Memory hook: Init true · Maintain true · Terminate with the answer.
C. Mathematical induction
  • Base case — prove the statement for the smallest input.
  • Inductive step — assume it holds for smaller inputs and prove it holds for the next size.
  • Used for recursive algorithms and for proving guessed solutions in the substitution method.
D. Example — insertion sort correctness

Loop invariant: at the start of each iteration of the outer for loop, the subarray arr[0..i−1] consists of the elements originally in arr[0..i−1] but in sorted order.

  • Initialization — for i = 1, the subarray arr[0..0] is trivially sorted.
  • Maintenance — the inner loop shifts larger elements right and inserts the key in its correct position, so after the iteration arr[0..i] is sorted.
  • Termination — when i = n, the entire array arr[0..n−1] is sorted → algorithm is correct.
Memory hook: Insertion sort invariant = sorted prefix grows by one each iteration.
