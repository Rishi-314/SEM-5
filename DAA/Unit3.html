1 Strategy & Characteristics
A. What is a greedy algorithm?
  • Solves a problem by making the best choice at the current step, hoping that these local best choices together give the global best solution.
  • One of the standard strategies (like divide and conquer) used to solve problems.
  • Used for solving optimization problems — problems demanding either maximum or minimum results.
B. Basic idea — the greedy loop
  1. Start with an empty solution.
  2. Select the best available option according to a greedy rule.
  3. Check feasibility.
  4. If feasible, include it.
  5. Repeat until the solution is complete.
Memory hook: Pick best now → check feasible → include → repeat. Never look back.
C. Objective function
  • Tells us what we are trying to optimize.

Examples

  • Maximize profit
  • Minimize cost
  • Minimize total time
  • Maximize number of activities
D. Characteristics of the greedy method
  1. Step-by-step construction — the solution is built one step at a time, not all at once.
  2. Local optimal choice — at every step, choose the best option currently available.
    • Example: in Fractional Knapsack, choose the item with the highest profit/weight ratio.
  3. Irreversible decisions — once a choice is made, it is never changed later. No backtracking.
  4. Feasibility check — before adding a choice, check whether it is valid under the problem constraints.
    • Example: when scheduling jobs, pick only jobs that fit into the timeline.
  5. Optimal substructure — after a greedy choice, the remaining problem is another smaller problem of the same type; the optimal overall solution can be built from optimal sub-solutions.
  6. Greedy choice property — a locally optimal choice can be part of a globally optimal solution. The best choice now must not prevent us from reaching the best final answer.
  7. Optimization objective — maximize (profit, value, number of activities) or minimize (cost, distance, time).
Memory hook: Step-by-step · Local best · No backtracking · Feasibility check · Optimal substructure · Greedy choice · Optimization goal.
E. Buffet analogy
  • You are at a buffet with limited space on your plate.
  • You want the maximum value from your plate.
  • At every moment, you pick the food that gives the most value for the space it occupies.
  • You don't reconsider what you already picked.
Greedy = "Best right now!" · Optimal = "Best overall!"
2 Greedy vs Optimal
A. Will greedy always give an optimal solution? — No
  • The greedy algorithm is not always optimal for every optimization problem.
  • It makes the best choice at the current moment, but that choice may sometimes prevent us from getting the best overall solution.
B. The college commute example

You want to reach college in the minimum total time. Two routes from home:

  • Route A — looks shorter, takes 10 minutes initially.
  • Route B — takes 15 minutes initially.

Greedy reasoning: "10 minutes is better → take Route A."

But after taking Route A, you hit a huge traffic jam:

Route A → 10 + 30 = 40 minutes ✗ Route B → 15 + 10 = 25 minutes ✓
ChoiceWhyTotal time
GreedyRoute A looked best now40 min
OptimalRoute B gave the best total time25 min
C. When does greedy work well?
  • Making the best local choice does lead to the best global solution.
  • There are sorting or priority-based conditions (selecting the highest, lowest or shortest).
  • Decisions are final — once taken, they are never changed later.
D. Feasible vs optimal solution

Problem P: travel from A to B with the constraints of 6 hours and minimum cost.

  • A feasible solution satisfies all the constraints (e.g. travelling by train or by air).
  • Since we must cover the journey at minimum cost, this is a minimization problem.
  • Among the feasible solutions, the one with the minimum cost (train, 6 hrs) is the optimal solution.
Feasible Satisfies all constraints. There may be many feasible solutions.
Optimal A feasible solution providing the best result. There is only one optimal solution.
Memory hook: Every optimal solution is feasible, but not every feasible solution is optimal.
3 Fractional Knapsack
A. Problem statement
  • A bag (knapsack) can carry a limited weight.
  • We have several items, each with a weight (W) and a profit (P).
  • Goal: maximize total profit without exceeding the bag capacity.
  • In fractional knapsack, we are allowed to take a fraction (part) of an item.
B. Three possible approaches — and why ratio wins
  1. Select items by maximum profit — fails, high profit may mean huge weight.
  2. Select items by minimum weight — fails, light items may be low value.
  3. Select items by profit / weight ratio — the optimal greedy rule.

Why greedy on ratio?

  • We select by Profit / Weight — profit per unit weight.
  • The item with the highest ratio gives the maximum profit for each kg of weight, so we take it first.
Memory hook: Fractional Knapsack → sort by P/W descending → fill.
C. Algorithm & complexity
GreedyFractionalKnapsack(items, n, capacity): // Step 1: compute value/weight ratio for each item for i = 1 to n: ratio[i] = P[i] / W[i] // O(n) // Step 2: sort items in descending order of ratio sort items by ratio in decreasing order // O(n log n) totalProfit = 0; remainingCapacity = capacity // Step 3: pick items one by one for i = 1 to n: // O(n) if weight[i] <= remainingCapacity: totalProfit += P[i] // take whole item remainingCapacity -= weight[i] else: fraction = remainingCapacity / weight[i] // take fraction totalProfit += P[i] * fraction remainingCapacity = 0 break // knapsack full return totalProfit

Time complexity — no recurrence needed, this is a greedy (not D&C or DP) algorithm:

ratio calculation → O(n) sorting → O(n log n) fill knapsack → O(n) ───────────────────────────── T(n) = O(n) + O(n log n) + O(n) = O(n log n)

4 Job Sequencing
A. Problem statement
  • An optimization problem: schedule a set of jobs to maximize total profit while each job is completed within its deadline.

Given N jobs, each with:

  • Job ID — unique identifier.
  • Deadline — the latest time by which the job must be completed.
  • Profit — earned if the job is completed within its deadline.

Each job takes exactly 1 unit of time.

B. Constraints
  • Each job takes exactly 1 unit of time.
  • Each job has a fixed deadline — must be completed before or on its deadline.
  • Profit is earned only if the job is completed on time.
  • Jobs cannot be preempted — once started, a job must complete.
  • A single job per time slot.
  • A uni-processor executes the jobs.
C. Algorithm & complexity

Input: array of N jobs with ID, deadline and profit.
Output: the sequence of scheduled jobs and the maximum profit.

  1. Sort all jobs in descending order of profit.
  2. Find the maximum deadline among all jobs.
  3. Create an array of time slots (size = maximum deadline).
  4. Select the job with highest profit and place it in the latest available slot before its deadline.
  5. If a free slot is found → schedule the job.
  6. If no slot is available → skip the job.
  7. Compute the total profit from the scheduled jobs.
Step 1 sort by profit desc → O(N log N) Step 2 find max deadline → O(N) Step 3 create slot array → O(N) Step 4 place jobs in latest slot → O(N²) ───────────────────────────────────────────── Final time complexity: O(N²) worst case
Greedy choice: "Select the most profitable job first and place it in the latest available slot before its deadline." This leaves earlier slots free for other jobs.

5 Huffman Coding
A. What is Huffman coding?
  • A greedy algorithm for lossless data compression.
  • Main idea: characters that occur more frequently get shorter binary codes; characters that occur less frequently get longer codes.
  • This reduces the total number of bits needed to store or transmit data.
  • Assigns variable-length codes based on frequency.
B. When to use
  • When data contains symbols with different frequencies.
  • When lossless compression is required.
  • Widely used in text compression, ZIP files, image formats (JPEG, PNG) and audio/video compression.
  • Works best when some symbols occur much more frequently than others.
C. Why compression is needed — the numbers

Suppose we have 15 characters in a data file.

  • Normal storage: 8 bits per character (ASCII) → 8 × 15 = 120 bits.
Char ASCII Binary A 65 01000001 B 66 01000010 C 67 01000011 D 68 01000100

Fixed-length coding — equal bits per character:

A → 00 B → 01 C → 10 D → 11 4 characters identified → 2 bits each → 4 × 8 = 32 bits (codebook) 15 characters encoded → 15 × 2 = 30 bits Total = 32 + 30 = 62 bits … slide states 70 bits with its own accounting
✎ Note The slide's arithmetic is loose here ("For character: 4*8=32 bits · Total = 8+30+32=70 bits"). The exact total depends on how the codebook is counted. What matters for the exam is the contrast: fixed-length wastes bits when frequencies are skewed, while Huffman assigns shorter codes to frequent symbols.
D. Huffman coding is greedy — why
  • At every step, pick the two smallest-frequency nodes — a locally optimal choice.
  • Combine them into a new node whose frequency is the sum.
  • Repeat until only one tree remains — the global optimum.
  • This greedy choice ensures that characters with higher frequency get shorter codes.
Memory hook: Huffman = repeatedly merge the two least frequent nodes.
E. Steps of the algorithm
  1. Count the frequency of each character.
  2. Create a leaf node for each character.
  3. Insert all nodes into a Min Heap (priority queue).
  4. Remove the two nodes with minimum frequency.
  5. Create a new node with frequency = sum of both.
  6. Insert the new node back into the heap.
  7. Repeat until only one node remains (the root).
  8. Traverse the tree: left edge → 0, right edge → 1. Path from root to leaf = Huffman code.
Huffman_Coding(characters, frequencies): Q = empty min-heap for each character c: insert node(c, freq(c)) into Q while size(Q) > 1: left = extract_min(Q) right = extract_min(Q) parent = new node(left.freq + right.freq) parent.left = left; parent.right = right insert parent into Q root = extract_min(Q) traverse root: assign 0 to left edges, 1 to right edges return codes for all characters
F. Complexity

Let n = number of distinct characters.

// Building Min Heap insert n nodes → O(n) // Building Huffman Tree — (n−1) iterations extract-min → O(log n) extract-min → O(log n) insert new node → O(log n) per iteration = 3·O(log n) = O(log n) (n−1) iterations → O(n log n) // Generating Codes tree traversal → O(n) ───────────────────────────────────────── Overall: O(n) + O(n log n) + O(n) = O(n log n)

H. Decoding & prefix-free property
  • Decoding — take the code and traverse the tree from the root to find the character. E.g. 101 → root → right(1) → left(10) → right(101) = D.
  • To send the message, we must send the compressed bits + the codebook. We do not need to send the frequencies.

Why Huffman codes are prefix-free

  • No code is the starting part of another code.
  • Every symbol is stored at a leaf node of the tree — codes are assigned only at leaves.
  • Since all symbols are at leaves, no symbol's code can ever be the beginning of another's code.
  • This guarantees the encoded message is uniquely decodable without ambiguity.
✎ Note The slide's savings figure (42.5%) uses the loose 70-bit fixed-length accounting. The exam-relevant point is that variable-length prefix-free codes reduce the total bits when frequencies are skewed — e.g. F at 45% of the data gets a 1-bit code instead of 8.
6 Prim's Algorithm (MST)
A. Minimum Spanning Tree — definition
  • A subset of edges in a connected, weighted, undirected graph that connects all vertices without forming cycles.
  • Has the minimum total edge weight among all spanning trees.
  • For n vertices, the MST has exactly n − 1 edges.
  • There can be multiple MSTs for the same graph (when edge weights tie).
  • The cost of a spanning tree is the sum of its edge weights.
B. Why is MST greedy?
  • It chooses the optimal solution present at the moment, not the optimal solution as a whole.
  • Both Prim's and Kruskal's are greedy algorithms.

Applications of MST

  • Network design (Internet, roads, electrical circuits)
  • Clustering in machine learning
  • Approximation algorithms for NP-Hard problems
C. How Prim's algorithm works
  1. Start with any vertex as the initial MST.
  2. Select the smallest edge that connects a new vertex to the MST.
  3. Repeat until all vertices are included in the MST.

Properties

  • Always maintains a connected MST while adding edges.
  • Uses a Priority Queue (Min Heap) for efficiency.

Why is it greedy?

  • At each step, it chooses the smallest edge that expands the MST.
  • The local optimal choice leads to a globally optimal MST.
D. Pseudocode
A = ∅ // edges of the MST (initially empty) U = {1} // start with a single vertex while (U ≠ V) // loop until all vertices are in U let (u, v) be the least weighted edge such that u ∈ U and v ∈ V − U A = A ∪ {(u, v)} // add edge to MST U = U ∪ {v} // mark v as included // u is already in the MST; v is not yet visited
E. Worked example — 5 vertices

Step 1: choose a vertex — let's pick B.

Step 2: edges from B are B–C (weight 10) and B–D (weight 4). Minimum is B–D (4) → add to MST.

Step 3: among all edges from the MST to unvisited vertices, the candidates are D–E and C–D. Add D–E (2) and explore C's neighbours E and A.

Step 4: select C–D (1) → add to MST.

Step 5: choose C–A (3). We cannot select C–E because it would create a cycle.

MST edges: B–D(4) · D–E(2) · C–D(1) · C–A(3) Cost of MST = 4 + 2 + 1 + 3 = 10 units
Memory hook: Prim's grows one connected tree, always adding the cheapest edge that touches a new vertex.
F. Time complexity

Using an adjacency matrix + simple min selection → O(V²)

  • Each vertex is checked for the minimum edge, leading to O(V²).
  • Best case: O(V²) · Worst case: O(V²)

Using a min-heap + adjacency list → O(E log V)

// 1. Extract-Min — O(log V) each, done V times total = O(V log V) // 2. Edge relaxation (decrease-key) — O(log V) per edge total = O(E log V) // 3. Combine O(V log V) + O(E log V) = O(E log V) // since E ≥ V in a connected graph
Memory hook: Prim's = O(V²) with a matrix · O(E log V) with a heap.
7 Kruskal's Algorithm (MST)
A. What is Kruskal's algorithm?
  • A minimum spanning tree algorithm that takes a graph as input and finds the subset of edges that:
    • form a tree that includes every vertex, and
    • has the minimum sum of weights among all trees that can be formed from the graph.
  • Falls under the class of greedy algorithms — finds the local optimum hoping for the global optimum.
  • Starts from the edges with the lowest weight and keeps adding edges until the goal is reached.
B. How it works — steps
  1. Sort all edges in ascending order of weight.
  2. Pick the smallest edge.
  3. Check whether adding it creates a cycle.
  4. If no cycle → add it to the MST.
  5. Repeat until the MST contains V − 1 edges.
C. Pseudocode with Union-Find
KRUSKAL(G): 1. A = ∅ // MST edge set 2. Sort all edges in increasing order // O(E log E) 3. Make each vertex a separate set // O(V) 4. for each edge (u, v) in sorted order: if Find(u) ≠ Find(v): // no cycle → safe A = A ∪ {(u, v)} Union(u, v) // merge sets 5. Stop when A contains (V − 1) edges

Why Union-Find? Find(u) ≠ Find(v) means u and v are in different components, so adding the edge cannot create a cycle. Union merges them into one component.

D. Time complexity
Sorting all edges → O(E log E) Find / Union per edge (with path compression + union by rank) → ≈ O(α(V)) ≈ O(1) amortised Process all E edges → O(E) ──────────────────────────────────────────── Total: O(E log E) (dominant term) // since E ≤ V², log E ≤ 2 log V, so this is also O(E log V)
