1 Polynomial Time & P Class Q3 · Q6 · Q8
Exam Answer — Q8 A polynomial time algorithm runs in O(n^k) for some constant k. Examples: binary search O(log n), merge sort O(n log n), Dijkstra O((V+E)log V). Non-polynomial examples: brute-force TSP O(n!), subset sum O(2ⁿ), 3-SAT O(2ⁿ).
A. Polynomial time algorithm — definition (Q8)
  • An algorithm whose running time is bounded by c·n^k for constants c > 0 and k ≥ 0, where n is the input size.
  • Written as O(n^k) — polynomial in input size.
  • Considered efficient / tractable: doubling the input roughly multiplies time by a constant factor, not exponentially.
poly examples: O(log n) O(n) O(n log n) O(n²) O(n³) NOT poly: O(2ⁿ) O(n!) O(nⁿ)
B. Examples — polynomial vs non-polynomial (Q8)

C. P class — definition (Q3, Q6)
  • P = the class of decision problems (yes/no answers) that can be solved by a deterministic machine (a normal computer) in polynomial time.
  • These are the tractable problems — solvable in theory and in practice.
P = ∪k≥0 DTIME(nk)
D. P class — examples with justification (Q6)
  • Sorting — Merge sort runs in O(n log n) on a DTM → P.
  • Searching — Binary search runs in O(log n) → P.
  • Shortest path — Dijkstra runs in O((V+E)log V) → P.
  • Primality test — AKS runs in polynomial time → P.
  • GCD — Euclid's algorithm runs in O(log n) → P.
  • Maximum matching — Hopcroft–Karp runs in O(E√V) → P.

Real life: Google Maps shortest route, spell-checker dictionary lookup, contact-list sorting.

Memory hook: P = Polynomial · easy to solve AND easy to check.
2 NP Class Q3 · Q6
Exam Answer — Q3 / Q6 NP (Non-deterministic Polynomial) = problems whose proposed solution (a certificate) can be verified in polynomial time by a deterministic machine. Equivalently, problems solvable in polynomial time on a Non-Deterministic Turing Machine. Slogan: hard to find, easy to verify.
A. NP — verifier definition
L ∈ NP ⟺ ∃ poly-time verifier V and poly bound p such that x ∈ L ⟺ ∃ y with |y| ≤ p(|x|) and V(x, y) = 1 y is the certificate / witness equivalent machine definition: NP = ∪k≥0 NTIME(nk)
  • The verifier V must be deterministic and run in polynomial time.
  • The certificate can be any string of polynomial length.
B. Hard to find, easy to verify
  • Finding a solution may take exponential time (search through possibilities).
  • Checking a given solution takes polynomial time (just verify it).
Memory hook: NP = Non-deterministic Polynomial — NOT "not polynomial".
C. NP examples with certificates (Q6)
ProblemCertificateVerification cost
SudokuA filled gridO(n²) — check rows, cols, boxes
Password crackingA guessed passwordO(1) — compare with stored hash
Subset SumA subset of numbersO(n) — add elements and compare with S
Hamiltonian CycleA cycleO(n) — check each vertex visited once
TSP (decision)A tourO(n) — sum distances and compare with k
SAT / 3-SATA truth assignmentO(n) — evaluate all clauses

Worked example — Sudoku: solving from scratch is very hard; but a filled 9×9 grid can be verified row-wise, column-wise and box-wise in O(n²).

Worked example — Subset Sum: {3,7,1,8,5}, target 12 → certificate {7,5}; verification is 7+5=12, O(n).

3 P vs NP Relationship Q3 · Q9
Exam Answer — Q9 No one knows. "Can all NP problems be converted into P?" is exactly the P = NP question, which is open. What is proven is P ⊆ NP (every easy-to-solve problem is easy to check). Most researchers believe P ≠ NP. If P = NP were true, every NP problem would become polynomial-time solvable — modern cryptography (RSA) would break instantly, and optimisation, scheduling, and drug discovery would become tractable.
A. The proven relation — P ⊆ NP (Q3)
  • If a problem is in P, you can solve it quickly.
  • Naturally, you can also verify a solution quickly — just solve it and compare.
  • Therefore every problem in P is automatically in NP.
P ⊆ NP ← proven P = NP ? ← open, widely believed false

One-line summary

  • P = "easy to solve and easy to check."
  • NP = "maybe hard to solve, but easy to check."
B. What P = NP would mean (Q9)
  • Cryptography collapses — RSA relies on factoring being hard (easy to verify, believed hard to solve). If P = NP, factoring becomes easy and online banking, private messages, digital signatures all break.
  • Optimisation becomes tractable — TSP, scheduling, protein folding, VLSI layout all solvable exactly in polynomial time.
  • AI and theorem proving — automated discovery of proofs and plans becomes efficient.
  • Randomisation loses purpose — why guess when you can compute exactly?
C. Evidence that P ≠ NP
  • Decades of research have not produced a polynomial-time algorithm for any NP-Complete problem.
  • If any single NP-Complete problem were solved in polynomial time, then all NP problems would be (because every NP problem reduces to it).
  • This "all-or-nothing" structure is strong evidence that the classes differ.
Memory hook: Solve one NP-Complete problem in polynomial time → P = NP.
D. Direct answer to Q9 (model exam answer)

Q: Can all NP problems be converted into P?

A: This is unknown — it is the famous open question P vs NP. If P = NP, then yes: every problem whose solution can be checked quickly can also be solved quickly. If P ≠ NP (the widely held belief), then no: some NP problems are inherently harder to solve than to verify, and NP-Complete problems are the candidates.

4 NP-Hard & NP-Complete Q1
Exam Answer — Q1 (relationship) NP-Hard = at least as hard as every problem in NP (∀L'∈NP, L'≤ₚL); need not be in NP. NP-Complete = NP-Hard AND in NP. So NPC = NP ∩ NP-Hard. Every NP-Complete problem is NP-Hard, but not every NP-Hard problem is NP-Complete. Every problem in NP reduces to any NP-Complete problem.
A. Polynomial-time reduction (the tool behind everything)
L₁ ≤p L₂ ← "L₁ reduces to L₂ in polynomial time" means: there is a poly-time computable f such that x ∈ L₁ ⟺ f(x) ∈ L₂ consequence: if L₂ is easy → L₁ is easy if L₁ is hard → L₂ is at least as hard as L₁
B. NP-Hard — formal definition
L is NP-Hard ⟺ ∀ L' ∈ NP, L' ≤p L
  • An NP-Hard problem need not be in NP.
  • It need not be decidable (the Halting Problem is NP-Hard).
  • It need not be a decision problem (TSP optimisation is NP-Hard).
  • Verification may be easy or impossible — the definition only constrains relative difficulty.
Intuition: "NP-Hard means SO hard that even checking a proposed answer may itself be hard."
C. NP-Complete — definition
NPC = NP ∩ NP-Hard
  1. L ∈ NP — given a solution, verify it in polynomial time.
  2. L is NP-Hard — every problem in NP reduces to L in polynomial time.

Key facts

  • All NP-Complete problems are NP-Hard; the converse is false.
  • NPC refers to the decision version (yes/no); the optimisation version may be NP-Hard but not in NP.
  • Solving any one NPC problem in polynomial time → all NP problems become solvable in polynomial time.
D. Relationship — how the four classes fit

E. NPC examples + how to prove NP-Complete

Standard NP-Complete problems

  • SAT — first NP-Complete problem (Cook–Levin theorem).
  • 3-SAT, Clique, Vertex Cover, Graph 3-Coloring.
  • Hamiltonian Cycle, Subset Sum, TSP (decision), Knapsack (decision).

How to prove a problem is NP-Complete

  1. Show L ∈ NP — give a polynomial-time verifier.
  2. Show L is NP-Hard — reduce a known NPC problem to L: SAT ≤ₚ L.

6 Deterministic vs Randomized Q2
Exam Answer — Q2 A randomized algorithm takes random numbers as an extra input and uses them to guide its choices during execution. Unlike a deterministic algorithm, the same input may produce a different output or take different time on different runs. Example: quicksort — deterministic pivot = first element gives O(n²) on sorted input; a random pivot gives O(n log n) expected regardless of input order.
A. How randomized algorithms use random choices
  1. Extra input — besides the normal input (array, graph), the algorithm reads a stream of random bits r.
  2. Random decision — at certain steps, the algorithm uses r to pick among several equally good options (which pivot, which vertex, which hash function).
  3. Behaviour varies — even with the same input, two runs may execute different sequences of steps.
  4. Random variable — output and running time are random variables over the distribution of r.
Pr[M(x) = f(x)] ← correctness probability E[T(x)] = Σ t · Pr[T(x) = t] ← expected running time
B. Deterministic definition + examples
  • Same input → same output, every time. Steps are fixed; there is only one execution path.
  • Correctness guaranteed — no randomness, no error probability.

Examples

  • Binary search — O(log n), always finds the element if present.
  • Merge sort — O(n log n) always.
  • Dijkstra's algorithm — deterministic shortest path.
  • Deterministic quicksort (pivot = first element) — but worst case O(n²) on sorted input.
C. Comparison table (Q2)
AspectDeterministicRandomized
Random bitsNoneUsed as extra input
Same input, repeatedSame output, same timeOutput and/or time may differ
CorrectnessGuaranteedGuaranteed (LV) or high probability (MC)
Worst caseCan be forced by adversarial inputAdversary cannot predict the coins
Average-case speedInput-dependentGood on every input
Typical gain—Simplicity, speed on average, symmetry breaking
D. Worked example — quicksort (Q2)

Deterministic quicksort (pivot = first element)

  • If input is already sorted, every partition is maximally unbalanced.
  • Recurrence: T(n) = T(n−1) + Θ(n) → T(n) = O(n²).
  • The adversary knows your rule and can always supply a worst-case input.

Randomized quicksort (random pivot)

  • At each call, pick an index uniformly at random between low and high, swap it with the last element, then partition.
  • Pivot rank is uniform over 0…n−1, so on average the split is balanced.
  • Recurrence: E[T(n)] = (1/n) Σ (E[T(i)] + E[T(n−1−i)]) + Θ(n) = O(n log n).
  • The adversary no longer controls the pivot choice, so no input can force the worst case with high probability.
Memory hook: Deterministic = predictable but attackable · Randomized = unpredictable but robust on every input.
7 Las Vegas Algorithms Q4 · Q5
Exam Answer — Q5 A Las Vegas algorithm always returns a correct answer, but its running time is random. Error probability = 0. Expected running time is polynomial. Example: randomized quicksort — always sorts correctly, but expected O(n log n) time (occasionally slower).
A. Definition
  • A randomized algorithm that always outputs a correct answer (or reports failure), but the time it takes is random.
  • Random choices speed up or simplify processing — sometimes it finishes quickly, sometimes slower — but it never returns a wrong result.
Pr[M(x) = f(x)] = 1 ← zero error, always E[T(n)] ≤ poly(n) ← expected time is polynomial class: ZPP (Zero-error Probabilistic Polynomial)
B. Properties
PropertyLas Vegas
CorrectnessAlways correct (zero error)
Running timeRandom; expected polynomial
Error probability0
How to fix slownessRerun — correctness is preserved
C. Example — randomized quicksort (pseudo-code)
RandomizedQuickSort(A, low, high): if low < high: p = random.randint(low, high) # random pivot swap A[p] with A[high] # move pivot to end pivotIndex = Partition(A, low, high) # Lomuto RandomizedQuickSort(A, low, pivotIndex - 1) RandomizedQuickSort(A, pivotIndex + 1, high) # Always returns a sorted array — Las Vegas.

Expected-time recurrence

E[T(n)] = (1/n) Σi=0n−1 ( E[T(i)] + E[T(n−1−i)] ) + Θ(n) = O(n log n) expected comparisons ≈ 2n ln n ≈ 1.39 n log₂ n
D. Other examples
  • Randomized quickselect — k-th smallest element, expected O(n).
  • Randomized 8-queens — place queens randomly; restart on conflict; always correct when it halts.
  • Universal hashing — expected O(1) per operation.
  • Karger's min-cut (Las Vegas variant) — repeat until the cut is verified optimal.
Memory hook: Las Vegas = always right, sometimes slow → rerun until fast enough.
8 Monte Carlo Algorithms Q4 · Q5
Exam Answer — Q5 A Monte Carlo algorithm runs in bounded (usually polynomial) time, but its answer may be wrong with probability ε. Error is reduced by repetition. Example: Miller–Rabin primality test — fast, but says "probably prime" with bounded error ≤ 1/4 per round.
A. Definition
  • A randomized algorithm that provides a result quickly, but the result may not always be correct.
  • Fast and simple — the answer is probably correct, not guaranteed.
  • Accuracy can be increased by increasing the number of independent trials.
Pr[M(x) = f(x)] ≥ 1 − ε ← error probability ε per run T(x) ≤ T(n) ← running time is bounded one-sided error (class RP) : "yes" always correct, "no" may be wrong two-sided error (class BPP) : both may be wrong, each prob ≤ 1/3
B. Properties
PropertyMonte Carlo
CorrectnessMay be wrong with probability ε
Running timeBounded / fixed (usually polynomial)
Error probabilityε (reducible)
How to fix errorRepeat and take majority (two-sided) or repeat until "no" (one-sided)
C. Error amplification (repetition)
# one-sided error, independent repetition Pr[error after k trials] ≤ εk # trials needed to reach target error δ k ≥ log(1/δ) / log(1/ε) # two-sided error, majority vote Pr[error after k trials] ≤ exp(−2kδ²) (Hoeffding)

This is the amplification lemma: any constant error below 1/2 can be driven to negligible probability by repetition.

D. Examples
  • Miller–Rabin primality test — one-sided error ≤ 1/4 per round.
  • Karger's min-cut — success ≥ 2/(n(n−1)) per run; repeat to amplify.
  • Monte Carlo integration (estimate π) — random points; error ≈ 1/√N.
  • Polynomial identity testing (Schwartz–Zippel) — error ≤ d/|S|.
# Miller–Rabin after k rounds k = 10 → 4−10 ≈ 9.5 × 10−7 k = 20 → 4−20 ≈ 9.1 × 10−13
Memory hook: use Monte Carlo when speed matters more than accuracy.
9 Las Vegas vs Monte Carlo Q4 · Q5
Exam Answer — Q4 (key difference) Las Vegas: always correct, running time is random, error probability = 0. Monte Carlo: running time bounded, but may be wrong with probability ε. In one line: Las Vegas trades time for certainty; Monte Carlo trades certainty for time.
A. Full comparison — correctness, running time, error probability (Q5)
CriterionLas VegasMonte Carlo
CorrectnessAlways correct (zero error)May be wrong with probability ε
Running timeRandom; expected polynomialBounded / fixed (usually polynomial)
Error probability0ε (reducible by repetition)
How to fixRerun if too slowRepeat and take majority or combine trials
Complexity classZPPRP (one-sided) / BPP (two-sided)
ExampleRandomized quicksort, quickselect, 8-queensMiller–Rabin, Karger min-cut, Monte Carlo integration
AnalogySearching for lost keys by random spots — always find them eventuallyOpinion polls — usually right, small chance wrong
B. Side-by-side with formulas
Las Vegas Pr[correct] = 1 E[T(n)] = polynomial → exact answer, random time Monte Carlo Pr[correct] ≥ 1 − ε T(n) = bounded polynomial → approximate answer, bounded time
C. Which one to use when
  • Use Las Vegas when you need an exact answer and can tolerate occasional slowness — sorting, selection, hashing.
  • Use Monte Carlo when you need speed and can tolerate a tiny, controllable error — primality testing, large-scale min-cut, simulations, approximate counting.
  • Repetition converts Monte Carlo towards Las Vegas: enough trials make the error probability smaller than the chance of hardware failure.
Memory hook: LV = Lways correct · MC = Might be correct.
10 Randomized + Approximation Q7
Exam Answer — Q7 Randomized algorithm — uses random numbers to guide choices, often faster on average. Example: randomized quicksort — expected O(n log n). Approximation algorithm — returns a solution within a guaranteed factor of optimal, in polynomial time. Example: 2-approximation for TSP via MST — returns a tour at most twice the optimal length.
A. Randomized algorithm — brief recap
  • Uses random bits as extra input to make choices during execution.
  • Same input may give different output or time — output/time are random variables.
  • Types: Las Vegas (always correct) and Monte Carlo (may be wrong with small probability).
  • Example: randomized quicksort — always sorts correctly, expected O(n log n).
B. Approximation algorithm — definition
  • For NP-Hard problems where exact solutions are too expensive, an approximation algorithm returns a solution that is provably close to optimal in polynomial time.
  • Defined by its approximation ratio ρ(n):
For a minimisation problem: cost(C) / cost(C*) ≤ ρ(n) for every input For a maximisation problem: cost(C*) / cost(C) ≤ ρ(n) where C = solution returned, C* = optimal solution ρ(n) = 2 means "never more than twice the optimal"
  • An algorithm with ratio ρ is called a ρ-approximation algorithm.
  • Goal: polynomial time + guaranteed quality.
C. Example 1 — 2-approximation for TSP (metric)
  1. Build an MST of the cities (Prim or Kruskal, polynomial).
  2. Do a pre-order traversal of the MST — this visits every vertex.
  3. Shortcut repeated vertices — output the resulting tour.
cost(MST) ≤ cost(optimal tour) traversal cost = 2 · cost(MST) ≤ 2 · cost(optimal) → factor ≤ 2 (2-approximation)
  • Runs in polynomial time (MST is O(E log V)).
  • Guarantees the returned tour is at most twice the optimal length.
D. Example 2 — 2-approximation for Vertex Cover
  1. While edges remain: pick any uncovered edge (u, v).
  2. Add both endpoints u and v to the cover.
  3. Remove all edges covered by u or v.
each chosen edge is disjoint (a matching) → optimal ≥ matching size algorithm picks 2 vertices per matched edge → |C| = 2 · matching → |C| / |C*| ≤ 2
E. Why approximation matters
  • TSP optimisation, vertex cover, set cover, scheduling are all NP-Hard — no known polynomial-time exact algorithm.
  • Approximation algorithms deliver a provable quality guarantee in polynomial time.
  • Together with randomization, they form the practical toolkit for intractable problems.
Memory hook: Approximation = fast + provably close · Randomized = fast + probably right.
